# Ming 证明工件消费指南（面向外部）

> **受众**：拿到 Ming 导出工件、准备自己写检查器/自己接工具链的第三方。
> **规范正本**：[docs/proof-protocol.md](proof-protocol.md)（§3 SMT-LIB 格式、§4.5 provenance manifest、§10 证书）。
> 本文是**消费侧导读**：命令、产物、判据摘要、验证配方、诚实边界、验收测试。规范与本文冲突时以规范为准。
> **状态**：v1.3.2（2026-11-27）。三件工件均已入库并有黄金锁定；证书判据自 v1.3.0 起冻结（§10.2）。
> **本文的立场**：Ming 仓库自己写这份指南，属于**降低消费摩擦**的工程动作；按 plan §4.21.6 口径，
> 它**不是**"外部消费者"——那需要一次非仓库所有方的真实消费。

## 1. 三件工件：各是什么、何时用哪个

三件工件都是**纯文本/纯 JSON、确定性输出**：同一输入 + 同一工具版本 → 逐字节相同（无时间戳、无随机序、
无绝对路径——**路径是命令行展示路径的原样回显**：你传相对路径则工件里是相对路径，传绝对路径则文件节
就含绝对路径，规范 §3.3/§10.6；项目模式另有解析路径例外，见同节）。都不改变任何判定与退出码（`0`/`1`/`2` 语义零变化）。

| 工件 | 命令 | 产物（stdout） | 你拿它做什么 |
|---|---|---|---|
| **SMT-LIB 脚本** | `ming check f.ming --proof-format smt-lib` | 一个完整 SMT-LIB 2.0 脚本（QF_LIA）：每个**可编码**义务两个方向各一个 `(push) … (assert 假设…) (assert (not 目标)) (check-sat) (pop)` 块；**目标不可线性化的义务不发射任何命令**（只有诚实注释，协议 §3.4） | 交给任意 SMT 求解器（z3/cvc5/…）逐块取 sat/unsat；**也是证书对照的参照面**（判据要求"不信任证书声明的系数"） |
| **自产线性证书** | `ming check f.ming --proof-format cert` | 证书文本（**全部行以 `;` 起行**的纯注释面，不是 SMT-LIB、不是 Alethe） | 无求解器、无 Ming 的**独立复核**：整数算术三条判据（§10.2），数十行代码可实现 |
| **provenance manifest** | `ming check f.ming --proof-format <smt-lib\|cert> --proof-manifest m.json` | 旁车 JSON（schema v2，9 键） | 回答"这份工件来自哪个工具版本、哪版采集逻辑、哪份源码"：`pass_hash` + `sources[].sha256` + `artifacts.{smt_lib_sha256,cert_sha256}` |

**选择建议**

- 只想确认"编码后的约束集是否不可满足"、且有求解器 → **SMT-LIB 脚本**。外部求解器可能比 Ming 内部判定**更强**
  （内部是差分约束子集，系数须 ±1、双变量一正一负；脚本编码的是完整线性合取），它不是分歧。
- 要在**无求解器环境**里机械复核、或要把证明链条写进审计材料 → **证书**。判据只需整数加减法。
- 要回答"工件与源码/工具链的对应关系"、或要做缓存/重证判定 → **manifest**。它证出处，**不证数学**
  （数学由证书或求解器回答），也**不证外部已复核**（`solver` 是留给你的回填位，Ming 恒填 `null`）。

**旗标约束（具名拒绝，不静默）**：`--proof-manifest` 必须与 `--proof-format smt-lib|cert` 同用；`-`（stdout）
被拒绝（工件与 manifest 会互相污染）；manifest 路径与源文件/工具链源文件重合 → 拒绝覆盖。
`--json` 模式下三件工件分别是 `proof_smt` / `proof_cert` / `proof_manifest` 字段，内容与文本模式逐字相同。

## 2. 一页判据（证书面，规范 §10.2–§10.4 摘要）

证书对**每个义务的 `proven` 且有证书的方向**给出一组引用 `(断言序号, 归一方向)` 与系数 `λ`
（非 `proven`、以及 `proven` 但无证书的方向只带 `; 无证书:<原因>` 具名行——它们没有引用可核）。复核分三步：

**第一步：归一**（把每条被引用的断言化成 `Σ cᵢxᵢ <= K`；规范 §10.3，**逐条冻结**）

| 断言形态 | 归一为 |
|---|---|
| `(<= a b)` | `a − b <= 0` |
| `(< a b)` | `a − b <= −1` ← **依赖整数域，是判据的一部分**；按实数读会得到错误的证书 |
| `(>= a b)` | `b − a <= 0`（取反对称） |
| `(> a b)` | `b − a <= −1`（取反对称） |
| `(= a b)` | 两条：`a − b <= 0`（`d0`）与 `b − a <= 0`（`d1`），引用须具名方向 |
| `(assert (not P))` | 先取 `P` 的对偶比较符（`not (>= …)` = `(< …)` 等），再按上表归一 |
| 常量项 | 折叠进 `K`：`Σ c x + d <= c₀` ⇒ `Σ c x <= c₀ − d` |

**第二步：逐变量恒等** `Σ_t λ_t c_t = 0`（每个变量上的系数和恰为 0）。

**第三步：负常数和** `Σ_t λ_t K_t < 0`。

三条同时成立 ⇒ 该方向的断言集 `A`（假设集 ⊕ 取反目标）在**整数域不可满足** ⇒ 目标在假设集下成立。
健全方向只走"实数不可行 ⇒（更弱的系统也不可行）⇒ 整数不可行"，`ℤⁿ ⊆ ℝⁿ` 使证书**绝不误证**；
代价只落在完全性（整数不可行但实数可行的系统没有 Farkas 证书——当前差分片段不出现）。

**引用序号与取反目标**：`#n` = 该方向 `(assert …)` 块内的 **1 起序**，与 `--proof-format smt-lib` **同块同序**；
取反目标恒为**块内末条**断言。`d0`/`d1` 只在 `(= a b)` 拆分上取 1（反向），其余恒 `d0`。

**λ 的现状**：本实现产出的 λ **恒为 1**（负环是简单环，同一断言在一个负环中至多引用一次；
`(= a b)` 拆出的两条边权常为 0 的二环，不可能同处一个负环）。判据**允许** λ > 1（多重引用），
格式已显式携带 λ——这是覆盖面的事实陈述，不是判据的限制。复核实现按 **λ ≥ 1** 校验；
规范 §10.2 写的是"非负整数"（**未改协议**），本指南与参考实现按"正整数字段、生产者恒 1"的口径阅读。

**覆盖率不承诺**（规范 §10.5）：证书只覆盖"**已采集**义务中判定来源为**单一负环**的 `proven` 方向"。
无证书的 `proven` 方向**具名标注**（`; 无证书:<原因>`），不伪装、不静默。机器可读的原因键
（manifest `obligations[].cert.reason`）：

`refuted` · `unknown` · `const-false` · `no-cycle` · `goal-split` · `goal-conjunction` ·
`unrenderable-assumption` · `missing`

对应形态：常量矛盾（`buf[0]` 的取反目标可归约成 LHS 为空的矛盾行，v1 不渲染）、`==` 目标双向拆分证明、
防御性路径（`cycle` 为空，理论不可达）、`!=` 目标（取反为合取）、假设集含不可渲染形态（错序守卫，
当前恒不触发）、目标未编码/超出差分片段、内部一致性缺口（出现即请报告）。

## 3. 验证配方（建议按序做，越往后越强）

### 步骤 1：先把证书读通（自洽检查）

```bash
ming check f.ming --proof-format cert > f.cert
```

自洽检查（只用证书本身）能确认：引用编号 1..n 连续、`(断言序号, 归一方向)` 按采集序、
λ ≥ 1、每条引用的行可解析、`Σλc = 0`、`ΣλK < 0`、自述 `identity:` 行与声明行一致。

**它不能确认**：系数是否被篡改、引用是否真的落在块内（`#999` 这种越界引用在自洽模式下可能静默通过）。
所以自洽只是**筛掉明显坏件**，不是复核。

### 步骤 2：与 SMT 脚本对照（这才是"复核"）

```bash
ming check f.ming --proof-format smt-lib > f.smt2      # 同一次输入、同一工具版本
```

对每条引用：按 `(文件节, vc:<fn>:<n>, dir)` 定位脚本里的方向块 → 取 `#n` 号断言 → **按 §10.3 重算归一** →
与证书声明的 `norm:` 行逐项比对（**声称的值一律不信**）→ 用重算值做 `Σλc`/`ΣλK` →
机械核验 `uses_goal`（引用了块内末条断言 ⟺ 取反目标被用到）。

本仓库给出一个可直接跑的**第二语言参考实现**（Python 3，仅标准库，不 import 任何 Ming/Node 代码）：

```bash
python examples/consumers/verify_cert.py tests/cert_fixtures/proven.cert --smt tests/proof_fixtures/proven.smt2
# 退出码 0 = 通过；1 = 失败（错误逐条具名走 stderr）
```

该实现启动即把 stdout/stderr 固定为 UTF-8（`PYTHONIOENCODING=cp1252/ascii/gbk` 下同样 exit 0 且
输出字节一致），读入按 UTF-8 解码并把 CRLF/孤立 CR 归一到 LF——非 UTF-8 终端可能显示转义，
但不会因编码失败误报。

**仓内可直接配对的只有两组**（同一语料、逐字节同源）：`tests/cert_fixtures/proven.cert` +
`tests/proof_fixtures/proven.smt2`、`tests/cert_fixtures/loop.cert` + `tests/proof_fixtures/loop.smt2`。
其余五个证书（`vacuous`/`const`/`eqsplit`/`chain`/`multifile`）**没有**仓内配对脚本，须用上面步骤 1/2
的命令自己生成。**陷阱**：`tests/proof_fixtures/multifile.smt2` 是 `multifile-a/b.ming` 语料
（`vc:pick:1`），与 `tests/cert_fixtures/multifile.cert`（`a/b.ming`，`vc:get:1`）**不是同一语料**——
硬配会因"找不到对应方向块 / 块在证书里没有对应方向节"而 exit 1，那是**配对错**，不是证书错。

七个入库证书语料在该实现下全部通过（各自配同源脚本）；`tests/cert_check.mjs` 的三负例全部被拒（见 §5）。
`examples/consumers/README.md` 列出两种模式的差别与输出样例。

**两条纪律**：①两件工件必须**同一份输入、同一工具版本**重新生成（跨导出没有互指纹，见 §4）；
②文件节是配对键的一部分——不同模块可以有同名 `vc:get:1`，只按 `(vc, dir)` 配会把多文件工件配错。

**参考实现的解析严格性边界（登记，不影响健全性）**：它不强制"每块恰一条 `(check-sat)`"、
不强制 `(declare-const)` 先于 `(assert)`、容忍非 `proven` 方向的多余字段、也不核文件节路径正确性——
这些属**生产者侧**的 §3.1 结构不变式（由 `tests/z3_check.mjs` 与 §113 锁定）。检查器不重复它们，
因为重复收紧只会在格式演进时制造假拒绝；但这也意味着它**不是**一个完整的 SMT 脚本校验器。

### 步骤 3：与 manifest 的 `artifacts` 哈希核对（闭合单次导出的 TOCTOU 窗口）

```bash
ming check f.ming --proof-format cert --proof-manifest f.cert.manifest.json > f.cert
# 文本模式且不加 --proof-report 时，stdout 就是完整工件
```

核验三元组（规范 §4.5）：

1. `manifest.artifacts.cert_sha256 == "sha256:" + sha256(f.cert 的完整字节)`（smt 侧对应 `smt_lib_sha256`）。
   哈希对象是**工件完整文本的 UTF-8 字节**，不做换行/空白规范化：

   ```bash
   python -c "import hashlib,sys;print('sha256:'+hashlib.sha256(open(sys.argv[1],'rb').read()).hexdigest())" f.cert
   ```

2. `manifest.obligations[]` 与工件内的文件节 / 义务节**按序对应**——两行的全形分别是
   `; ===== 文件:<展示路径> =====` 与
   `; ---- vc:<fn>:<n> — 索引 <索引原文>(scope: <body|loop>)----`；逐条对齐 `id` + `scope`
   （cert 模式每条还带 `cert{low,high}` 四字段）。
3. 若你用了 `--proof-report`（stdout = 摘要行 + 工件），哈希前须**剔除工件前的摘要行**：
   SMT 从首行 `(set-logic QF_LIA)` 起、证书从证书头注 `; ===== Ming 线性不可满足证书(cert v1)=====` 起。

**这一层闭合什么**：manifest 描述的就是**这次导出**的那份工件。**不闭合什么**：smt-lib 与 cert 是
**两次独立导出**、各自 manifest 各自绑定各自工件——**跨导出（smt ↔ cert）没有互指纹**，
两份 manifest 之间也不互相引用。要交叉复核，唯一的可靠对应是 `(文件节, vc, dir, #n)` 四元组，
且必须对同一份输入、同一工具版本重新生成两件工件（这是如实登记的窗口，v2 不假装已消除）。

## 4. 诚实边界（不得夸大）

1. **证书只证"编码后的约束集不可满足"**。以下**不经证书检验**（受信基座，规范 §10.7）：
   AST → 线性形式（含 `||`/非线性叶子的**丢弃**，丢弃只削弱假设集，方向上安全，但"丢了哪些"不经证书）、
   线性形式 → 文本（渲染与符号重写）、约束 → 引用（`#n` 是否真是该块断言——靠"同序号 + 归一值逐块重算"
   的一致性测试钉住，不是数学证明）、源码 → 义务（采集门槛）、**运行时安全**。
2. **`proven` 不消除 M4003 边界 panic**，证书不是"程序正确性证明"。
3. **覆盖率不承诺**：证书只覆盖已采集义务中单一负环来源的 `proven` 方向；证明面扩面（更多控制流/非线性）
   后出现无证书的 `proven` 是**预期**，属登记在案的非承诺项，不是缺陷。
4. **无证书的 `proven` 是具名跳过**，不是"已验证"也不是"已失败"：读 `; 无证书:<原因>` 或 manifest 的
   `cert.reason`（§2 末尾清单）。
5. **`uses_goal` 与 `vacuous` 是两个独立字段**：`uses_goal` 是证书属性（是否引用了取反目标，机械可核）；
   `vacuous` 是**生产者侧判定**（有效假设集自身不可满足）——消费者**无法独立重算**它（没有独立来源：
   需要另一次差分求解），只能如实转述，不得把它当"边界已证"。`vacuous: true` 的 `proven` 不是缺陷，
   但**不得汇报成"边界已证"**。
6. **manifest 的 `engine_contract` 是自由文本、不可机检**；`solver` 是**消费者回填位**（Ming 恒 `null`，
   不是"尚无结论"）；`pass_hash`/`sources` 只说明"来自哪份源码与哪版采集逻辑"，不说明结论正确。
7. **参考检查器与被检查物同仓**：`tests/cert_check.mjs`（JS）与 `examples/consumers/verify_cert.py`
   （Python）都证明"证书与 SMT 块在归一与恒等式上一致且三负例可被拒"，**不**证明编码忠实于源码。
   两者也是**本仓库自有代码**，按 plan §4.21.6 口径**不计入外部消费者**。
8. **不提供 Alethe**：Ming 不产出、不校验 Alethe；外部求解器产证明是由**用户**发起、用户解释的旁路
   （协议 §6.4），不进入构建链、不进入 CI 门槛。QF_LIA 算术证明能否被独立检查器全检属**未核实项**。

## 5. 邀请外部检查器：把三负例当验收测试

任何人实现自己的证书检查器时，请用下面三个负例做**判别力验收**（都能在临时目录里从一份好证书改出来，
不需要入任何代码库）。判定标准不只是"被拒绝"，而是**因对应判据被拒绝**——因无关原因被拒说明检查器失明：

| # | 变异 | 期望被拒的理由 |
|---|---|---|
| 1 | **篡改一行系数**：把某条 `; ref … norm: {x: c} <= K` 的系数 ±1 | 声明系数 ≠ 从 SMT 断言重算的系数 |
| 2 | **删一条引用**：删掉某方向的最后一条 `; ref` 行，`; refs:` 计数减一、随后引用重编号 | `Σλc` 在某变量上 ≠ 0（漏引用） |
| 3 | **越块引用**：把某条引用的断言序号改成块内不存在的值（如把**末条**引用改成 `#999`，保持引用序号升序） | 引用序号越界（块内只有 m 条断言） |

**注意 #3 的陷阱**：任何**保持引用序号升序**的序号改动（无论是否越界、是否指向另一条真实断言），
在"只做自洽"的检查器里都会**静默通过**——自洽模式只看得见"序号是否连续/升序"这一层形状，
**序号与断言之间的对应关系只有与 SMT 脚本对照才能核**。这正是必须"先自洽筛坏件、再脚本对照"的实证，
也是我们给任何第三方实现的建议顺序：自洽 → 脚本对照 → manifest 核出处。

**判据冻结承诺**（协议 §10.2，自 v1.3.0）：归一规则（含 `(< a b)` ⇒ `a−b <= −1` 的整数语义）、
`Σλc = 0 ∧ ΣλK < 0` 判据、`vc:<fn>:<n>` 与 `(文件节, 断言序号 #n, d0/d1)` 的对应规则**不变**。
变更须走 `docs/stability-contract.md` §4 的弃用流程；证书文本的**排版/字段序**属实验面
（消费者应解析结构、不应比较排版），字节确定性由 `tests/cert_fixtures/` 黄金锁定。

**我们希望的反馈**：判据在你自己语言里的实现是否与本文一致、哪条措辞有歧义、
你的语料上是否出现"证书通过但约束集其实可满足"（这会是健全性缺陷，按仓库流程报 issue）。
一次真实的第三方案例（非仓库所有）才会让"外部消费者 ≥ 1"的计数成立——那是 plan §4.22.3 裁决 3
所指的唯一解锁钥匙，本文只负责把摩擦降到可接受。
