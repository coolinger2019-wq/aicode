# Ming 契约桥协议(MVP)

> 版本:v1.2(S-4 契约桥 MVP,plan §4.21.2 / docs/roadmap-infrastructure.md §5.2)
> 状态:**MVP / 实验性**——格式与判定语义可能随真实用例演进;确定性输出与 M3052
> 判定口径在 MVP 期内保持稳定,不承诺与未来版本逐字节兼容。
> 单一事实来源:本文件定义 `.mingi` 格式与比较规则;实现为 `src/bridge.js`;
> 诊断码登记见 `src/diag.js` CODES 与 `docs/diagnostics.md`。

---

## 1. 范围

契约桥把**另一门语言的导出函数**的类型签名与契约候选,提取为 Ming 可核对的
**契约桩**(`.mingi` 文件),并在 Ming 侧 `extern fn` 声明处做一致性检查。

MVP 边界(固定,不扩面):

- 源语言:**仅 TypeScript**;契约来源:**仅 JSDoc 注释**;
- 边界形态:**仅 Ming `extern fn` ↔ TS `export function`**(C FFI 面);
- **不做**:Python、WASM Component、运行时插桩、契约在 Ming 侧的自动注入/执行、
  NLP/LLM 语义推断。

契约桩是**声明性工件**:它记录"跨语言边界双方应共同遵守的签名与候选边界条件"。
MVP 中它只用于签名一致性核对(M3052)与 JSON 注记,**不会**自动变成 Ming 的
`requires`/`ensures`(候选文本需人工审阅后写入 Ming 源码)。

## 2. 命令面

```bash
ming bridge extract --from ts <file.ts|目录> --out <目录> [--json]
ming check <file.ming...> --stub <目录|文件> [--json]
```

`bridge extract`:

- `--from` 只接受 `ts`;缺省或其他取值 → 显式报错 exit 1(不静默);
- 输入为文件时必须 `.ts` 结尾;为目录时递归收集 `.ts`(跳过隐藏项与 `node_modules`),
  目录为空 → 报错 exit 1;只接受一个位置输入(多余参数 → 报错 exit 1,不静默忽略);
- 每个 TS 文件生成**同名 `.mingi`**(`x.ts` → `x.mingi`,`.d.ts` → `.d.mingi`);
  目录输入在输出目录内**保留相对子目录结构**(避免同名文件互相覆盖);
- 文本模式逐文件一行回执;`--json` 输出 `{ok, from, out, files:[{source,input,output,functions,skipped}]}`;
- 函数被跳过不算失败:桩头具名注记,exit 0。输入不可读/输出不可写 → exit 1。

`check --stub`:

- 桩参数可以是单个 `.mingi` 文件,或一个目录(递归收集 `.mingi`,跳过隐藏项与 `node_modules`);
- 对**有同名桩条目**的 `extern fn` 做签名核对;无桩的 `extern fn` **零报告**;
- 失配 → **M3052[bridge-signature-mismatch]**(error,退出码 1);
- 桩文件不可解析 → 工具输入错误(具名消息,exit 1),不静默忽略;
- `--json` 增加 additive 字段 `stub_contract`(见 §6.3);不带 `--stub` 时输出逐字节不变。

## 3. `.mingi` 格式(版本 1)

行式文本,UTF-8,`\n` 换行。**确定性**:同一 TS 输入产生逐字节相同的输出——
无时间戳、无主机路径、无随机/哈希序;函数与跳过注记均按源码出现顺序。

### 3.1 头部

```
// mingi 1
// source: <TS 文件名或目录内相对路径>
// generated by: ming bridge extract --from ts(MVP;格式规范见 docs/bridge-protocol.md)
// skipped: <函数名> (line <N>): <跳过原因>
```

- 第 1 行固定 `// mingi <版本>`;当前版本 = **1**;解析器拒绝其他版本;
- `source` 的取值口径:单文件输入 = 文件名(basename);目录输入 = 相对输入目录的
  路径(以 `/` 分隔,保留子目录);
- `skipped` 行每个被跳过的导出函数一行,**具名**给出原因(诚实跳过,不是静默丢弃);
- 头部其余 `//` 注释行解析时忽略。

### 3.2 函数条目

```
fn <name>(<参数名>: <Ming 类型>, ...) -> <Ming 返回类型>
  // from <source>:<N>
  requires <候选前置条件>
  ensures <候选后置条件>
```

- `fn` 行 = 由 TS 签名映射得到的 **Ming 类型签名**(纯声明,不是 Ming 源码);
- `// from` 回链 = TS 源文件的 `source` 与函数声明的行号(1 起);
- `requires` / `ensures` 行可 0..N 条,顺序 = 提取顺序(参数声明序 × 描述内出现序,
  然后是 `@returns` 描述内出现序),同文本去重;
- 条目之间以空行分隔;空行与缩进不承载语义(解析器按 trim 后逐行识别);
- 子句文本是**候选边界条件**,不是可执行 Ming 表达式:其中 `len$x` 是本协议定义的
  长度符号(见 §4.3),写进 Ming 源码时需改写为 `x.len()`。

### 3.3 解析器拒绝形态

以下情况整份桩不可用(调用方报告具名错误,exit 1):缺头部、版本不支持、
`fn` 行语法不成立、`requires`/`ensures` 不属于任何条目、无法识别的行、
同文件重复函数名条目。

## 4. 类型映射表(MVP)

TS 类型文本先做规范化(折叠空白、`[ ]` → `[]`),再按**精确匹配**查表;
表外类型 → 该函数**跳过**并在桩头具名注记(不猜、不降级、不做结构体/联合类型推断)。

### 4.1 标量与容器

| TypeScript 类型 | Ming 类型 |
|---|---|
| `number` | `f64` |
| `bigint` | `i64` |
| `string` | `str` |
| `boolean` | `bool` |
| `number[]` | `Vec[f64]` |
| `readonly number[]` | `Vec[f64]` |
| `readonly string[]` | `Vec[str]` |

### 4.2 返回类型

返回类型使用同一映射表:必须是**显式标注**且可映射。未标注返回类型、`void`、
`Promise<T>`、`any`/`unknown`/联合/字面量类型、结构体/元组 — 一律跳过该函数
(具名原因)。MVP 只支持**同步**导出函数。

### 4.3 长度符号 `len$x`

JSDoc 中 `x.length`(x 为 `Vec[...]` 参数)映射为边界符号 **`len$x`**——
与 Ming 静态边界证明内部使用的长度符号同构(GUIDE §6)。它只出现在 `.mingi`
的候选子句里;改成可编译的 Ming `requires` 时写 `x.len()`。

### 4.4 载体与污点

Ming `extern fn` 的返回 `str` 必须声明为 `Untrusted[str]`(v0.61 门禁,否则 M3049)。
因此桥接核对采用**载体一致**口径:`Untrusted[T]` 与 `T` 视为同一映射类型
(污点标注是 Ming 侧的安全细化,不改变跨语言 ABI 形状)。见 §6.2 规则 3。

## 5. JSDoc 契约提取规则(确定性模式)

只解析 **`@param` 与 `@returns`(或 `@return`)描述**;自由描述段、`@throws`、
`@example` 等一律忽略。契约提取**不做 NLP/LLM**:解析不了 → 桩只含签名,不发明语义。

### 5.1 可识别的模式

二元算术不等式:`<operand> <op> <operand>`,其中:

- `<op>` ∈ `<=`, `>=`, `<`, `>`;
- `<operand>` ∈ 参数名 | 字面量(仅**十进制**整数/小数,可负) | `<Vec 参数名>.length` |
  `result`(仅 `@returns` 描述);
- **词边界 = 最大连续 token**(字符集 `[A-Za-z0-9_$.\[\]]`):操作符两侧各取最大
  token 整体匹配文法——`max >= 0` 不会截成 `x >= 0`(`max` 是完整 token,未知名 →
  整条丢弃);token 含成员访问(`y.z`)、下标(`zs[0]`)、非十进制数字形态
  (`1e9`/`0x10`/`1_000`/`10n`)→ **整条不等式丢弃,不截断不发明**;
- 操作数外接算术运算符(`0 <= n - 1`、`x + 1 < len`)→ 不是简单二元式,整条丢弃;
- 同一段描述里的多个不等式全部提取;链式写法(如 `0 <= n <= 10`)按重叠候选
  提取为两条(`0 <= n`、`n <= 10`)。

### 5.2 归属规则

- `@param <名> ...` 描述中的不等式 → **requires 候选**(按参数声明序);
- `@returns ...` 描述中**引用 `result`** 的不等式 → **ensures 候选**;
- requires 中出现 `result` 的不等式 → 丢弃(入口处 result 不存在);
- `@returns` 中不引用 `result` 的不等式 → 丢弃(无法判断其语义);
- 操作数只能是本函数参数、`result`、`len$参数`、字面量;其他标识符(含未知名字、
  非 Vec 参数的 `.length`、成员访问)→ 该条不等式丢弃;
- 至少约束一个参数(requires)/ 必须约束 result(ensures);纯常量子句丢弃;
- 同文本子句去重(首个出现位置保留)。

### 5.3 不支持的 JSDoc 形态(如实跳过)

- `@param {类型} 名 ...` 的类型花括号被忽略(类型以 TS 签名为准,不从 JSDoc 取);
- 可选参数标注 `@param [名]` 不提取契约(签名侧也会因 `?` 跳过该函数);
- **包裹标点不影响识别**:反引号/花括号/尖括号/逗号等非 token 字符天然是操作数边界
  (`{a >= 0}`、`` `b <= 5` ``、`<c > 1>` 均能提取)——不识别的是**操作数本身**
  不属于文法(见 §5.1 词边界规则);
- 自然语言(如 "must be non-negative")不识别;
- 注释与函数声明同行、JSDoc 与函数之间隔着其他代码 → 不关联该函数。

### 5.4 TS 扫描限制(非完整 AST)

实现是逐行正则/行扫描。**导出函数识别面**:

- 只认单行的 `export function <名>(...) [: <类型>] {`(或 `;` 声明),以及 `.d.ts` 的
  `export declare function <名>(...) : <类型>;`(2026-11-23 审查 m3 补支持);
- 以下形态**跳过并具名注记**:`export async function`、`export default function`、
  泛型函数(`function f<T>`)、跨行签名、解构/默认值/可选/rest 参数、尾逗号参数、
  参数或返回类型不在映射表、重载/同名重复声明(取首个)。
- **不扫描(静默跳过,不产条目也不产注记)**:`export const f = ...`(箭头函数/
  函数表达式)、`export { f }` 再导出、class 方法、装饰器、`.tsx`。
  这些不是"误提取",而是 MVP 范围外(具名登记于此;GUIDE/能力矩阵不得表述为
  "具名注记"——审查 m3 修正)。

## 6. 消费侧:`ming check --stub`(M3052)

### 6.1 核对对象

对检查到的每个模块(含 `use` 加载的模块)中的每个 `extern fn`:

- 桩索引中无同名条目 → **零报告**(MVP 只核对有桩的;不要求每个 extern 都有桩);
- extern 声明 span 上与 **error 级诊断重叠**(如类型名未解析 M3001)→ **毒化跳过**
  (签名本身不可信,根因诊断优先;v0.67 诊断纪律。计入 `skipped_poisoned`,不发 M3052);
- 有同名条目 → 逐位核对;一个 extern fn 最多发 **1 条 M3052**(把所有差异列入
  message,差异间用 `;` 分隔)。

### 6.2 比较规则

1. **参数个数**:桩与 extern 必须相同;
2. **参数类型**(按位置):规范化后必须相同(参数名不参与——跨语言名字无约束);
3. **载体等价(两侧对称)**:比较前**桩侧与 extern 侧都**剥掉最外层
   `Untrusted[...]`(见 §4.4;2026-11-23 审查 m1 修正——此前只剥 extern 侧,
   桩写 `Untrusted[str]` 与 extern 同文本会误报失配);
4. **返回类型**:必须相同;缺返回类型 = `unit`——extern 缺返回类型与桩写 `unit`
   在文本上一致(互不矛盾);桩写任何其他返回类型均不一致。

规范化:移除全部空白;两侧都经同一"剥载体 + 去空白"管线后比对(桩侧
`Untrusted[str]`、`Vec[f64]` 等与 extract 产出的裸载体文本天然可比);
Ming 侧类型由 AST 重建为同一文本形态。

### 6.3 `--json` 注记

带 `--stub` 时 `check --json` 输出增加 additive 字段:

```json
"stub_contract": {
  "stub": "<--stub 参数原样>",
  "entries_loaded": 2,
  "checked": [
    {
      "fn": "clamp",
      "file": "demo.ming", "line": 5,
      "stub": "examples/bridge_demo/demo.mingi", "stub_line": 6,
      "signature": "fn clamp(x: f64, lo: f64, hi: f64) -> f64",
      "stub_signature": "fn clamp(x: f64, lo: f64, hi: f64) -> f64",
      "requires": ["x >= lo", "x <= hi", "lo <= hi"],
      "ensures": ["result >= lo"],
      "matched": true
    }
  ],
  "mismatched": 0,
  "skipped_poisoned": 0
}
```

- `checked` 只含**有同名桩**的 extern fn(按模块加载序 × 声明序;多入口共享模块按
  绝对路径 + 函数名去重);
- `entries_loaded` = 桩索引条目数(同名条目跨桩文件去重后);
- `skipped_poisoned` = 因 error 级诊断重叠而跳过核对的 extern 数(见 §6.1 毒化跳过);
- 不带 `--stub` 时该字段不存在(既有 JSON 输出逐字节不变)。

### 6.4 诊断

```
M3052 bridge-signature-mismatch
桥接签名失配:extern 函数 "clamp" 与契约桩 <桩路径>:<行> 不一致——参数 #1 类型 桩=f64、extern=i64;返回类型 桩=f64、extern=i64
```

span = extern 声明整体;hint 指向本协议与两条修复路径(改 extern 或重新 extract)。

## 7. 确定性与稳定性

- extract 输出仅依赖输入文本与输入路径的**相对形态**;同一输入、同一目录布局下
  重复运行逐字节一致(测试锁定双跑相等 + 仓库黄金);
- 目录扫描顺序 = 相对路径的码元序(`<` 比较,与 locale 无关);
- 节点顺序 = 源码出现序(函数、跳过的函数各自保序);
- **不承诺**跨版本 `.mingi` 逐字节兼容:格式版本号变更即格式变更信号;
- M3052 的码号/名称属稳定诊断协议(CODES 单一事实来源)。

## 8. 诚实限制清单(MVP)

1. **不是 TypeScript 编译器**:行扫描/正则会误判字符串或注释里的 `export function`
   文本(极罕见);不构建 AST、不解析导入类型、不展开类型别名;
2. **契约候选不是语义**:JSDoc 不等式只做文本级映射,不验证与实现一致,
   也不注入 Ming 运行/静态检查;人工审阅后才应写入 `requires`/`ensures`;
3. **只有一种源语言与一种边界形态**:Python / WIT / WASM Component 不在本协议;
4. **`len$x` 仅为候选符号**:`.mingi` 不可直接编译;转成 Ming 源码需人工改写;
5. **不核对参数名、效果、ABI 布局、C 结构体/数组形参**:只核对参数个数与映射类型
   (载体口径);结构体/数组 FFI ABI 本身也是 Ming C 后端的未覆盖面;
6. **同名桩跨文件取首个**:目录内多个 `.mingi` 定义同名函数时,按路径码元序首个
   生效,其余被忽略(未告警——登记为限制);
7. **`.mingi` 是工具输入**:手工编辑可能引入解析错误;解析错误一律 exit 1 具名,
   不会静默跳过某个函数(报告首条错误 + 总错误数);
8. **TS 侧 `void`/可选参数/async/泛型/重载/箭头导出**均不支持(见 §5.3/§5.4),
   这些函数不会进入桩;**能被识别为声明形态的才在桩头具名注记,箭头导出/
   `export {f}`/class 方法属"不扫描"(静默,零条目零注记)**;
9. **陈旧桩不清理**:`--out` 下改名/删除 TS 后残留的 `.mingi` 不会自动清理,
   可能造成意外 M3052——核对前请清空/重建输出目录(登记为限制);
10. **隐藏单文件**:显式传 `.foo.ts` 单文件会生成 `.foo.mingi`,但目录扫描把隐藏项
    跳过 → 该桩静默不参与核对(登记为限制);
11. **空 `--stub` 目录**:`entries_loaded=0` 时零核对、零告警(与"只核对有桩的"一致);
12. **`--from`/`--stub` 是全局旗标值**:其他子命令里以前会落到位置参数的
    `--from X`/`--stub X` 现在被解析层吞掉(无已知合法用法,登记);
13. **`--json` 路径字段**按调用方传入形态回显(Windows 上可能 `\`/`/` 混用;
    不影响 `.mingi` 内容与 id 的确定性)。
