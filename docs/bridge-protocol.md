## 1. 范围

契约桥把**另一门语言的导出函数**的类型签名与契约候选,提取为 Ming 可核对的
**契约桩**(`.mingi` 文件),并在 Ming 侧 `extern fn` 声明处做一致性检查。

MVP 边界(固定,不扩面):

- 源语言:**仅 TypeScript**;契约来源:**仅 JSDoc 注释**;
- 边界形态:**仅 Ming `extern fn` ↔ TS `export function`**(C FFI 面);
- **不做**:Python、WASM Component、运行时插桩、契约在 Ming 侧的自动注入/执行、
  NLP/LLM 语义推断。

契约桩是**声明性工件**:它记录"跨语言边界双方应共同遵守的签名与候选边界条件"。
MVP 中它用于签名一致性核对(M3052)、**调用点 requires 满足性检查**(S-5,§7)与
JSON 注记,**不会**自动变成 Ming 的 `requires`/`ensures`(候选文本需人工审阅后写入
Ming 源码),也不会注入任何证明/推导。

**桥接元数据(v1.2.3 / R-18)**——类型是对方语言已经知道的部分;效果与污点是
Ming 能查、TypeScript 不能查的维度,桩必须携带:

- **效果面**:JSDoc `@effects` → `.mingi` 条目 `effects` 行。它是**元数据**:
  Ming `extern fn` 隐含 `ffi`、语言面无法再声明效果,因此 `check --stub` **不做
  语言层核对**,只把桩声明的效果如实注记进 `--json` 的 `stub_contract.checked[]`
  供下游工具/Agent 消费(§6.3);
- **污点面**:JSDoc `@taint` → 参数/返回类型 `Untrusted[str]`(沿用 v0.61 载体),
  参与**既有载体等价**签名比对(§6.2 规则 3——污点标注不产生假失配),并在
  `stub_contract` 注记里如实呈现桩侧标注(§6.3)。

## 2. 命令面

```bash
ming bridge extract --from ts <file.ts|目录> --out <目录> [--json]
ming check <file.ming...> --stub <目录|文件> [--json]
```

`bridge extract`:

- `--from` 只接受 `ts`;缺省或其他取值 → 显式报错 exit 1(不静默);
- 输入为文件时必须 `.ts` 结尾;为目录时递归收集 `.ts`(跳过隐藏项与 `node_modules`),
  目录为空 → 报错 exit 1;只接受一个位置输入(多余参数 → 报错 exit 1,不静默忽略);
- 每个 TS 文件生成**同名 `.mingi`**(`x.ts` → `x.mingi`,`.d.ts` → `.d.mingi`);
  目录输入在输出目录内**保留相对子目录结构**(避免同名文件互相覆盖);
- 文本模式逐文件一行回执;`--json` 输出
  `{ok, from, out, files:[{source,input,output,functions,skipped,effects,taint,notes}]}`
  (`effects`/`taint`/`notes` 为 v1.2.3 起 additive 字段,见 §3.4);
- 函数被跳过不算失败:桩头具名注记,exit 0。输入不可读/输出不可写 → exit 1。

`check --stub`:

- 桩参数可以是单个 `.mingi` 文件,或一个目录(递归收集 `.mingi`,跳过隐藏项与 `node_modules`);
- 对**有同名桩条目**的 `extern fn` 做签名核对;无桩的 `extern fn` **零报告**;
- 失配 → **M3052[bridge-signature-mismatch]**(error,退出码 1);
- 对指向有桩 extern 的**调用点**做 requires 满足性检查(S-5,§7):字面量实参可判时,
  违反 → **M3053[bridge-contract-violated]**(error,退出码 1);不可判只计数,不猜;
- 桩文件不可解析 → 工具输入错误(具名消息,exit 1),不静默忽略;
- `--json` 增加 additive 字段 `stub_contract`(见 §6.3);不带 `--stub` 时输出逐字节不变。

## 3. `.mingi` 格式(版本 2;版本 1 仍可解析)

行式文本,UTF-8,`\n` 换行。**确定性**:同一 TS 输入产生逐字节相同的输出——
无时间戳、无主机路径、无随机/哈希序;函数与跳过注记均按源码出现顺序。

### 3.1 头部

```
// mingi 2
// source: <TS 文件名或目录内相对路径>
// generated by: ming bridge extract --from ts(MVP;格式规范见 docs/bridge-protocol.md)
// skipped: <函数名> (line <N>): <跳过原因>
// note: <函数名> (line <N>): <被丢弃标注的原因>
```

- 第 1 行固定 `// mingi <版本>`;当前版本 = **2**(v1.2.3 / R-18 起);
- **版本策略**:渲染器只发 2;解析器**接受 1 与 2**——v1 桩(无 `effects` 行)零
  改动可读,旧黄金继续有效;其余版本拒绝。v1 文件里出现 `effects` 行按解析错误
  报告(不静默接受错版本形态)。选择"发 2 + 双版本读"而不是"v1 严格 + 可选行",
  是因为 `effects` 行是**格式扩展而非标注**:版本号必须能区分"有/无该行"的两种
  文件,否则手工桩在 v1 下写 effects 会被静默忽略,违背"不静默"纪律;
- `source` 的取值口径:单文件输入 = 文件名(basename);目录输入 = 相对输入目录的
  路径(以 `/` 分隔,保留子目录);
- `skipped` 行每个被跳过的导出函数一行,**具名**给出原因(诚实跳过,不是静默丢弃);
- `note` 行(v1.2.3 起)= **函数保留、但某个桥接元数据标注被丢弃**的具名注记
  (未知效果名 / 不支持的 `@taint` 形态 / 载体白名单外的污点映射),按源行号升序;
  与 `skipped` 分开,避免"函数被跳过"的误读。`note` 行与 `skipped` 行一样只是
  注释:解析器忽略,`--json` 的 `notes` 字段是它的机器可读形态;
- 头部其余 `//` 注释行解析时忽略。

### 3.2 函数条目

```
fn <name>(<参数名>: <Ming 类型>, ...) -> <Ming 返回类型>
  // from <source>:<N>
  effects <效果名>, <效果名>, ...
  requires <候选前置条件>
  ensures <候选后置条件>
```

- `fn` 行 = 由 TS 签名映射得到的 **Ming 类型签名**(纯声明,不是 Ming 源码);
- `// from` 回链 = TS 源文件的 `source` 与函数声明的行号(1 起);
- `effects` 行 = **可选**(版本 2 起;渲染器只发 0..1 行;解析器接受多行并按出现序
  合并去重——手工桩形态):JSDoc `@effects` 的合法效果名,逗号 + 空格分隔、按 JSDoc
  出现序去重;无效果声明的条目**零输出**(v1 形态)。
  效果名是**元数据**:只注记、不做语言层核对(理由见 §1);名字是否属于 Ming
  已知效果集由 extract 侧校验(未知名逐名丢弃 + `note` 注记,合法名照常保留),
  解析器只做语法校验(`[a-z][a-z0-9_]*`),手工桩的未知名字如实透传;
- `requires` / `ensures` 行可 0..N 条,顺序 = 提取顺序(参数声明序 × 描述内出现序,
  然后是 `@returns` 描述内出现序),同文本去重;
- 条目之间以空行分隔;空行与缩进不承载语义(解析器按 trim 后逐行识别);
- 子句文本是**候选边界条件**,不是可执行 Ming 表达式:其中 `len$x` 是本协议定义的
  长度符号(见 §4.3),写进 Ming 源码时需改写为 `x.len()`;
- 污点面**不占独立行**:`@taint` 直接改写类型文本为 `Untrusted[str]`(§4.4),
  `parseMingi` 按类型文本自然读出。

### 3.3 解析器拒绝形态

以下情况整份桩不可用(调用方报告具名错误,exit 1):缺头部、版本不支持(1 与 2
之外)、`fn` 行语法不成立、`requires`/`ensures`/`effects` 不属于任何条目、
`effects` 行出现在版本 1 文件、`effects` 行没有有效名字或名字不合法、无法识别的行、
同文件重复函数名条目。

### 3.4 extract `--json` 的元数据字段(v1.2.3 起 additive)

```json
"files": [
  {
    "source": "demo.ts", "input": "...", "output": "...",
    "functions": ["clamp", "readConfig"],
    "skipped": [{ "name": "parseAny", "line": 34, "reason": "..." }],
    "effects": { "clamp": [], "readConfig": ["fs"] },
    "taint": { "clamp": { "return": false, "params": [] },
                "readConfig": { "return": true, "params": [] } },
    "notes": [{ "name": "readConfig", "line": 12, "reason": "@effects 未知效果 \"x\" 已丢弃(...)" }]
  }
]
```

- `effects` / `taint` 的键序 = 条目源码出现序;`effects` 值 = 该条目保留的合法效果名;
- `taint.return` = 返回类型是否为 `Untrusted[...]`;`taint.params` = 带污点标注的
  参数名(声明序);
- `notes` = 桩头 `note` 行的机器可读形态(与 `skipped` 分开);
- 不带 `--json` 时文本回执行格式逐字不变。

## 4. 类型映射表(MVP)

TS 类型文本先做规范化(折叠空白、`[ ]` → `[]`),再按**精确匹配**查表;
表外类型 → 该函数**跳过**并在桩头具名注记(不猜、不降级、不做结构体/联合类型推断)。

### 4.1 标量与容器

| TypeScript 类型 | Ming 类型 |
|---|---|
| `number` | `f64` |
| `bigint` | `i64` |
| `string` | `str` |
| `boolean` | `bool` |
| `number[]` | `Vec[f64]` |
| `readonly number[]` | `Vec[f64]` |
| `readonly string[]` | `Vec[str]` |

### 4.2 返回类型

返回类型使用同一映射表:必须是**显式标注**且可映射。未标注返回类型、`void`、
`Promise<T>`、`any`/`unknown`/联合/字面量类型、结构体/元组 — 一律跳过该函数
(具名原因)。MVP 只支持**同步**导出函数。`string` 返回可用 `@taint return` 标污为
`Untrusted[str]`(§4.4);载体白名单外的映射标注被忽略并注记。

### 4.3 长度符号 `len$x`

JSDoc 中 `x.length`(x 为 `Vec[...]` 参数)映射为边界符号 **`len$x`**——
与 Ming 静态边界证明内部使用的长度符号同构(GUIDE §6)。它只出现在 `.mingi`
的候选子句里;改成可编译的 Ming `requires` 时写 `x.len()`。自 v1.4 起,同一符号
在调用点满足性检查(§7)中按"对应实参是字面量 Vec 时的元素个数"求值。

### 4.4 载体与污点

Ming `extern fn` 的返回 `str` 必须声明为 `Untrusted[str]`(v0.61 门禁,否则 M3049)。
因此桥接核对采用**载体一致**口径:`Untrusted[T]` 与 `T` 视为同一映射类型
(污点标注是 Ming 侧的安全细化,不改变跨语言 ABI 形状)。见 §6.2 规则 3。

**JSDoc `@taint` → 桩类型映射(v1.2.3 / R-18)**:

| JSDoc | 桩类型 | 说明 |
|---|---|---|
| `@taint return`(返回类型 `string`) | 返回 `Untrusted[str]` | 外部内容源向上游标污 |
| `@taint param <名>`(该参数类型 `string`) | 该参数 `Untrusted[str]` | 外部输入向下游标污 |

**载体白名单(桥接面)= `str`**。Ming 侧 `Untrusted` 载体白名单 =
`str`/`Json`/`Vec[u8]`/`Map[str,str]`/`i64`(checker M3050),但 TS 映射表只有
`string` 映射为可作为 extern 边界载体的 `str`(ADR-012 §8:extern 返回污标量不预支);
`Vec[u8]`/`Json`/`Map[str,str]` 无 TS 映射来源。因此:
`@taint` 指向 `f64`/`i64`/`bool`/`Vec[f64]`/`Vec[str]` 等映射时,**忽略该标注**并在
桩头 `note` 具名(诚实跳过,不猜、不降级);其余合法标注照常保留。

污点标注**不改变核对结果**:桩写 `Untrusted[str]` 与 extern 写 `str`(或反之)
都按载体 `str` 视为一致(§6.2 规则 3);`stub_contract` 只把桩侧标注如实注记为
信息面(§6.3)。

## 5. JSDoc 契约提取规则(确定性模式)

只解析 **`@param` 与 `@returns`(或 `@return`)描述**、**`@effects`** 与 **`@taint`**
(后两者 v1.2.3 / R-18;§5.5);自由描述段、`@throws`、`@example` 等一律忽略。
契约提取**不做 NLP/LLM**:解析不了 → 桩只含签名,不发明语义。

### 5.1 可识别的模式

二元算术不等式:`<operand> <op> <operand>`,其中:

- `<op>` ∈ `<=`, `>=`, `<`, `>`;
- `<operand>` ∈ 参数名 | 字面量(仅**十进制**整数/小数,可负) | `<Vec 参数名>.length` |
  `result`(仅 `@returns` 描述);
- **词边界 = 最大连续 token**(字符集 `[A-Za-z0-9_$.\[\]]`):操作符两侧各取最大
  token 整体匹配文法——`max >= 0` 不会截成 `x >= 0`(`max` 是完整 token,未知名 →
  整条丢弃);token 含成员访问(`y.z`)、下标(`zs[0]`)、非十进制数字形态
  (`1e9`/`0x10`/`1_000`/`10n`)→ **整条不等式丢弃,不截断不发明**;
- 操作数外接算术运算符(`0 <= n - 1`、`x + 1 < len`)→ 不是简单二元式,整条丢弃;
- 同一段描述里的多个不等式全部提取;链式写法(如 `0 <= n <= 10`)按重叠候选
  提取为两条(`0 <= n`、`n <= 10`)。

### 5.2 归属规则

- `@param <名> ...` 描述中的不等式 → **requires 候选**(按参数声明序);
- `@returns ...` 描述中**引用 `result`** 的不等式 → **ensures 候选**;
- requires 中出现 `result` 的不等式 → 丢弃(入口处 result 不存在);
- `@returns` 中不引用 `result` 的不等式 → 丢弃(无法判断其语义);
- 操作数只能是本函数参数、`result`、`len$参数`、字面量;其他标识符(含未知名字、
  非 Vec 参数的 `.length`、成员访问)→ 该条不等式丢弃;
- 至少约束一个参数(requires)/ 必须约束 result(ensures);纯常量子句丢弃;
- 同文本子句去重(首个出现位置保留)。

### 5.3 不支持的 JSDoc 形态(如实跳过)

- `@param {类型} 名 ...` 的类型花括号被忽略(类型以 TS 签名为准,不从 JSDoc 取);
- 可选参数标注 `@param [名]` 不提取契约(签名侧也会因 `?` 跳过该函数);
- **包裹标点不影响识别**:反引号/花括号/尖括号/逗号等非 token 字符天然是操作数边界
  (`{a >= 0}`、`` `b <= 5` ``、`<c > 1>` 均能提取)——不识别的是**操作数本身**
  不属于文法(见 §5.1 词边界规则);
- 自然语言(如 "must be non-negative")不识别;
- 注释与函数声明同行、JSDoc 与函数之间隔着其他代码 → 不关联该函数。

### 5.4 TS 扫描限制(非完整 AST)

实现是逐行正则/行扫描。**导出函数识别面**:

- 只认单行的 `export function <名>(...) [: <类型>] {`(或 `;` 声明),以及 `.d.ts` 的
  `export declare function <名>(...) : <类型>;`(2026-11-23 审查 m3 补支持);
- 以下形态**跳过并具名注记**:`export async function`、`export default function`、
  泛型函数(`function f<T>`)、跨行签名、解构/默认值/可选/rest 参数、尾逗号参数、
  参数或返回类型不在映射表、重载/同名重复声明(取首个)。
- **不扫描(静默跳过,不产条目也不产注记)**:`export const f = ...`(箭头函数/
  函数表达式)、`export { f }` 再导出、class 方法、装饰器、`.tsx`。
  这些不是"误提取",而是 MVP 范围外(具名登记于此;GUIDE/能力矩阵不得表述为
  "具名注记"——审查 m3 修正)。

### 5.5 桥接元数据标签(`@effects` / `@taint`,v1.2.3 / R-18)

两者都是**标签行本身**参与解析(行扫描风格);标签后的描述续行不参与(不像
`@param` 描述那样累积),不识别自然语言。

```
@effects io, fs, net        ← 逗号分隔;去空白;只接受小写名字(不折叠大小写)
@taint return               ← 返回类型标污(`@taint returns` 同义)
@taint param raw            ← 该参数标污
```

- `@effects` 的每个名字:属于 Ming 已知效果集(`src/checker.js` KNOWN_EFFECTS,
  单一事实来源)则保留(出现序去重);**未知/非法名字逐名丢弃**,并在桩头
  `// note:` 具名(合法名字照常保留——不做整条丢弃,也不猜近似名);
- `@taint return` / `@taint param <名>`:按 §4.4 映射为 `Untrusted[str]`;
  形态不认识(`@taint foo` 等)、参数名不存在、或载体不在桥接白名单 → **忽略该
  标注** + 桩头 `// note:` 具名;
- 同一函数多条 `@taint` 累加(去重);多条 `@effects` 累加(出现序去重);
- 标签可以出现在 JSDoc 任意位置(与 `@param`/`@returns` 互不影响);
- 元数据标注**不影响函数是否进入桩**:只影响条目的 `effects` 行与类型文本。

## 6. 消费侧:`ming check --stub`(M3052)

### 6.1 核对对象

对检查到的每个模块(含 `use` 加载的模块)中的每个 `extern fn`:

- 桩索引中无同名条目 → **零报告**(MVP 只核对有桩的;不要求每个 extern 都有桩);
- extern 声明 span 上与 **error 级诊断重叠**(如类型名未解析 M3001)→ **毒化跳过**
  (签名本身不可信,根因诊断优先;v0.67 诊断纪律。计入 `skipped_poisoned`,不发 M3052);
- 有同名条目 → 逐位核对;一个 extern fn 最多发 **1 条 M3052**(把所有差异列入
  message,差异间用 `;` 分隔)。

### 6.2 比较规则

1. **参数个数**:桩与 extern 必须相同;
2. **参数类型**(按位置):规范化后必须相同(参数名不参与——跨语言名字无约束);
3. **载体等价(两侧对称)**:比较前**桩侧与 extern 侧都**剥掉最外层
   `Untrusted[...]`(见 §4.4;2026-11-23 审查 m1 修正——此前只剥 extern 侧,
   桩写 `Untrusted[str]` 与 extern 同文本会误报失配);
4. **返回类型**:必须相同;缺返回类型 = `unit`——extern 缺返回类型与桩写 `unit`
   在文本上一致(互不矛盾);桩写任何其他返回类型均不一致。

规范化:移除全部空白;两侧都经同一"剥载体 + 去空白"管线后比对(桩侧
`Untrusted[str]`、`Vec[f64]` 等与 extract 产出的裸载体文本天然可比);
Ming 侧类型由 AST 重建为同一文本形态。

### 6.3 `--json` 注记

带 `--stub` 时 `check --json` 输出增加 additive 字段:

```json
"stub_contract": {
  "stub": "<--stub 参数原样>",
  "entries_loaded": 2,
  "checked": [
    {
      "fn": "readConfig",
      "file": "demo.ming", "line": 5,
      "stub": "examples/bridge_demo/demo.mingi", "stub_line": 16,
      "signature": "fn readConfig(path: str) -> Untrusted[str]",
      "stub_signature": "fn readConfig(path: str) -> Untrusted[str]",
      "requires": [],
      "ensures": [],
      "effects": ["fs"],
      "taint": { "return": true, "params": [] },
      "matched": true
    }
  ],
  "mismatched": 0,
  "skipped_poisoned": 0,
  "contracts": { "checked": 1, "violated": 0, "unchecked": 2 }
}
```

- `checked` 只含**有同名桩**的 extern fn(按模块加载序 × 声明序;多入口共享模块按
  绝对路径 + 函数名去重);
- `effects`(v1.2.3 起)= 桩条目 `effects` 行的效果名数组(无声明 → `[]`)。**纯元数据**:
  不参与 M3052 判定——extern fn 隐含 `ffi`,Ming 语言面没有第二位可声明效果,
  受检查面在设计里不存在;该字段供下游工具/Agent 消费(如生成 FFI 包装的
  效果门禁、审计跨语言副作用的可信面);
- `taint`(v1.2.3 起)= 桩侧污点标注的信息面投影:`return` = 返回类型是否
  `Untrusted[...]`,`params` = 带污点的参数名(声明序)。判定仍走载体等价
  (§6.2 规则 3),该字段只如实呈现;
- `entries_loaded` = 桩索引条目数(同名条目跨桩文件去重后);
- `skipped_poisoned` = 因 error 级诊断重叠而跳过核对的 extern 数(见 §6.1 毒化跳过);
- `contracts`(v1.4 起,S-5 additive)= 调用点满足性检查计数
  `{checked, violated, unchecked}`(键序固定,位于 `stub_contract` 末位;三者互斥,
  语义见 §7.3)。无该检查面(无 requires 桩/无调用点)时三者均 `0`;
- 不带 `--stub` 时该字段不存在(既有 JSON 输出逐字节不变)。

```
M3052 bridge-signature-mismatch

```

span = extern 声明整体;hint 指向本协议与两条修复路径(改 extern 或重新 extract)。

## 7. 契约满足性检查(S-5 / MVP,ADR-015)

> v1.4(`ming check --stub` 的第二判定面):在签名核对(M3052)之外,对**调用点**
> 做桩 `requires` 的静态满足性检查。裁决与边界见
> `docs/adr-015-contract-satisfaction.md`(MVP = b-lite;ensures 满足性与假设注入
> 否决于本批)。诚实边界:可判面**极窄**(实参全字面量的调用点),`contracts`
> 计数强制暴露 checked/unchecked 比例——"报告满足"不得表述为覆盖全部调用点。

### 7.1 审查对象

- 只在 `ming check <files> --stub <目录|文件>` 下发生;**不带 `--stub` 时零行为、
  零输出变化**(M3053 与 `contracts` 均不出现);
- 对每个 checked 模块(含 `use` 加载的模块)中指向**有同名桩的 `extern fn`** 的调用点:
  - 裸调用 `f(...)`(callee 为标识符;名字解析按 checker 优先级——局部绑定 > 模块项 >
    内建);
  - `use` 引入模块的成员调用 `m.f(...)`:**当前不可达,仅防御性保留**——`extern fn`
    永非 `pub`(parser 的 `pub` 白名单只允许 fn/struct/enum/const;checker 注册 extern
    时 `pub:false`),跨模块访问必先报 M3001(span 为 callee、止于 `(`,与 Call span
    起点相接 → 毒化跳过)。该分支只在未来可见性口径变化时才有活路。
- 只审查**带 ≥1 条 `requires` 的桩**;无 requires 的桩调用不进入计数(无契约可判);
- 同一调用点最多 1 条 M3053(全部违反子句列入同一 message);
- 调用表达式与既有 error 级诊断重叠(毒化)→ 不审查、不计数(根因诊断优先,v0.67
  诊断纪律;与 M3052 的 `skipped_poisoned` 同源);
- **同名遮蔽不归属 extern**(块级本地 `fn` / `let` 绑定的函数值 / 形参等)。实现取
  保守口径:函数体内**任何位置**出现同名绑定 → 该名字在本函数内一律不审查、不计数
  (只漏不误报;ADR-015 §5 风险表);
- **深嵌套守卫**:checker 已报 M4005 的顶层声明(checker `depthBailed` 集)直接跳过
  (防只读遍历二次裸崩,v0.75 纪律);遍历器自身带深度上限(500),超限函数整体不审查
  不计数(对称放弃);兜底 catch `RangeError` 同样具名跳过。

### 7.2 可判子集(只认文档化文法,绝不猜)

一条 `requires` 行必须**整体可解析**,且**全部操作数可赋值**:

| 元素 | 认的形态 | 不认 → 该调用点 unchecked |
|---|---|---|
| 比较符 | `<` `<=` `>` `>=` | `==`/`!=`/`&&`/`\|\|`/算术邻接(`n - 1`)/其余字符 |
| 字面量 | 十进制整数/小数(可负) | `1_000`/`0x10`/`1e9` 等非十进制形态 |
| 参数 | 桩签名的参数名(按**位置**映射到调用实参) | 未知标识符、`result`(requires 不引用返回值) |
| 长度符号 | `len$x`(x 为桩参数;对应实参须是**字面量 Vec**) | 变量/表达式实参(长度不可得) |
| 实参形态 | `IntLit`/`FloatLit`/`StrLit`(无插值)/`BoolLit`/`VecLit`,含一元负号字面量 | 变量、表达式、调用、插值串 |

- 链式写法 `0 <= n <= 10` 按**相邻对**求值(`0 <= n` 且 `n <= 10`);
- 数值比较:两侧均为整数 → **BigInt 精确比较**(i64 边界不丢失);整数字面量与 `f64`
  字面量混合时,整数侧须在 ±(2^53−1) 内可精确转 `Number`,否则不可判(精度取舍即猜测);
- `str`/`bool`/`Vec` 值不参与不等式(不可判,不猜——例如桩写 `requires s >= 0` 的
  str 参数调用恒 unchecked);
- 实参个数与桩参数个数不一致 → 整个调用点 unchecked。**常见形态不计数**:调用与
  extern 的实参个数也不符时先被 M3005 毒化跳过(不审查、不计数);只有 extern 与调用
  一致而桩不同(M3052 面)才真正计入 unchecked;
- **任一行不可解析/任一操作数不可赋值 → 整个调用点 unchecked**(不部分求值:手工桩
  `requires weird_thing &&` 不产生任何诊断);
- 字面量 Vec 的 `len$x` 可判(ADR-015 §3 的"当前语言面不可达"假设已由实测修正:
  `check` 层接受 `sz([1.0, 2.0])` 形态;运行时仍走 `ming cc` 的 FFI 面)。

### 7.3 判定与 M3053

- 全部子句可判且全部成立 → 计入 `checked`;
- 任一子句可判且为假 → **M3053[bridge-contract-violated]**(error,退出码 1):
  message 含违反子句原文、代入值(参数/长度符号按子句操作数序,如 `x = -1`)与桩
  `file:line`;span = 调用表达式(Call 节点 span;与语言内其他调用点诊断同口径,起点为
  实参括号);hint 指向本协议;
- 不可判 → 零诊断,只计入 `--json` 的 additive `stub_contract.contracts`:

```json
"contracts": { "checked": 1, "violated": 1, "unchecked": 3 }
```

- 计数语义(**三者互斥**;`checked + violated + unchecked` = 审查覆盖的调用点总数):
  - `checked` = 判定**满足**的调用点数(不含违反);
  - `violated` = 判定违反的调用点数(一个调用点无论违反几条子句只计 1);
  - `unchecked` = 指向带 requires 桩但**不可判定**的调用点数(非字面量实参 / 子句不可
    解析 / 实参个数不符 / `len$` 不可得 / 实参含插值等);
- 毒化跳过与遮蔽归属的调用点**不进入任何计数**(它们不是该 extern 的可审查调用点)。

### 7.4 语义边界(明确不做;ADR-015 §2/§4)

- **不改变任何推导**:桩 `requires` 不注入 checker/prover,不参与边界证明,不改变
  M3041/M3045/W3105 的结论——本检查**只报告调用点事实**;
- **运行时零接触**:tree/VM/wasm/cc 执行路径零改动(FFI 语义仍是 `ming cc` 的职责);
- **ensures 满足性不做**(静态/运行时均不做):extern 无实现体,静态不可判;运行时
  采样会改变语义。选项 c(桩 ensures 注入证明假设集)**否决于本批**,重开须独立 ADR
  + 假设来源标注设计;
- **非字面量实参的证明不做**(b-full:等价于新的过程间边界分析,预支证明扩面);
- **跨语言行为验证不做**(无执行环境,信任边界如实);**效果面满足性不做**(效果是
  元数据,语言面无 extern 效果声明位)。

## 8. 确定性与稳定性

- extract 输出仅依赖输入文本与输入路径的**相对形态**;同一输入、同一目录布局下
  重复运行逐字节一致(测试锁定双跑相等 + 仓库黄金);
- 目录扫描顺序 = 相对路径的码元序(`<` 比较,与 locale 无关);
- 节点顺序 = 源码出现序(函数、跳过的函数各自保序);`note` 行按源行号升序
  (稳定排序,同行保持产生序);`effects` 名字按 JSDoc 出现序去重;`taint.params`
  按参数声明序;
- **不承诺**跨版本 `.mingi` 逐字节兼容:格式版本号变更即格式变更信号
  (版本 2 相对版本 1 的唯一差别 = 可选 `effects` 行与 `note` 头部行;无这两者的
  v2 桩与 v1 桩逐字节相同);
- M3052/M3053 的码号/名称属稳定诊断协议(CODES 单一事实来源);M3053 的判定是
  **调用点事实**(与 requires 是否注入推导无关);
- 调用点审查顺序:模块按 checked 顺序 × 加载序(同一物理模块按绝对路径只扫一次),
  函数体/调用节点按源码序;`contracts` 计数与诊断 message 内子句序 = 桩 requires 序。

## 9. 诚实限制清单(MVP)

1. **不是 TypeScript 编译器**:行扫描/正则会误判字符串或注释里的 `export function`
   文本(极罕见);不构建 AST、不解析导入类型、不展开类型别名;
2. **契约候选不是语义**:JSDoc 不等式只做文本级映射,不验证与实现一致,
   也不注入 Ming 运行/静态检查;人工审阅后才应写入 `requires`/`ensures`;
3. **只有一种源语言与一种边界形态**:Python / WIT / WASM Component 不在本协议;
4. **`len$x` 仅为候选符号**:`.mingi` 不可直接编译;转成 Ming 源码需人工改写;
5. **不核对参数名、效果、ABI 布局、C 结构体/数组形参**:只核对参数个数与映射类型
   (载体口径);结构体/数组 FFI ABI 本身也是 Ming C 后端的未覆盖面;
6. **效果面不可语言层核对(R-18 如实登记)**:`extern fn` 在 Ming 语言面隐含
   `ffi`,没有第二位可声明效果——"桩效果 vs extern 效果"的比较面**在语言设计里
   不存在**。桩携带 `effects` 行,但本工具只把它注记进 `stub_contract`(下游工具/
   Agent 消费);效果声明与实现是否一致、与调用点 `with` 门禁是否匹配,均不在
   MVP 核对范围;
7. **效果声明来源只有 JSDoc**:`@effects` 是唯一来源;`.d.ts`/项目声明文件/
   TypeScript 类型系统里没有效果位(MVP 不读取其他声明形态);`@effects` 的
   名字表手工维护(`src/checker.js` KNOWN_EFFECTS 单一事实来源),不影响运行时;
8. **污点面只覆盖 `str` 载体**:TS 映射表里只有 `string` 能映射到 extern 边界
   合法污点载体 `str`;`Vec[f64]`/`Vec[str]` 等映射的 `@taint` 被忽略并注记
   (§4.4)。污点标注是 **ABI 形状之外的安全细化**,Bridge 不验证被调用方是否真的
   把不可信内容标了污;
9. **同名桩跨文件取首个**:目录内多个 `.mingi` 定义同名函数时,按路径码元序首个
   生效,其余被忽略(未告警——登记为限制);
10. **`.mingi` 是工具输入**:手工编辑可能引入解析错误;解析错误一律 exit 1 具名,
    不会静默跳过某个函数(报告首条错误 + 总错误数);
11. **TS 侧 `void`/可选参数/async/泛型/重载/箭头导出**均不支持(见 §5.3/§5.4),
    这些函数不会进入桩;**能被识别为声明形态的才在桩头具名注记,箭头导出/
    `export {f}`/class 方法属"不扫描"(静默,零条目零注记)**;
12. **陈旧桩不清理**:`--out` 下改名/删除 TS 后残留的 `.mingi` 不会自动清理,
    可能造成意外 M3052——核对前请清空/重建输出目录(登记为限制);
13. **隐藏单文件**:显式传 `.foo.ts` 单文件会生成 `.foo.mingi`,但目录扫描把隐藏项
    跳过 → 该桩静默不参与核对(登记为限制);
14. **空 `--stub` 目录**:`entries_loaded=0` 时零核对、零告警(与"只核对有桩的"一致);
15. **`--from`/`--stub` 是全局旗标值**:其他子命令里以前会落到位置参数的
    `--from X`/`--stub X` 现在被解析层吞掉(无已知合法用法,登记);
16. **`--json` 路径字段**按调用方传入形态回显(Windows 上可能 `\`/`/` 混用;
    不影响 `.mingi` 内容与 id 的确定性);
17. **S-5 可判面极窄**:只有"实参全为字面量"的调用点可判;变量/表达式/调用/插值串
    实参一律 unchecked(不猜,也不做区间传播证明——b-full 不做)。用 `contracts`
    的 checked/unchecked 比例如实评估覆盖面,不得表述为"契约被普遍满足";
18. **S-5 遮蔽/毒化是保守的**:函数体内任何位置出现同名绑定 → 该名字在本函数内全部
    不审查(可能漏报真实 extern 调用点);调用表达式重叠 error 诊断 → 不审查不计数;
19. **S-5 不做跨模块重命名解析/元组展开**:只按裸调用 `f(...)` 归属(`m.f(...)` 的
    成员调用分支**当前不可达、仅防御性保留**:extern 永非 `pub`,跨模块访问必先 M3001
    毒化跳过);经变量中转的函数值(`let g = m.f; g(...)`)不审查(不是该 extern 的
    直接调用点);
20. **S-5 只报告、不证明**:M3053 是"该调用点字面量违反桩 requires"的**事实**,不是
    运行时保证;桩自身可能写错(候选文本来自 JSDoc),修正方向以 TS 侧契约为准;
21. **桩索引按裸函数名全局唯一(pre-existing,与 M3052 同源)**:两个模块声明同名
    `extern fn` 且桩不同型时,调用点按**首载桩**(目录码元序首个)求值——同名同型
    才安全;跨模块同名但语义不同时必须拆桩名(登记为限制,不在本批扩面)。
