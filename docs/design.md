# Ming 设计文档(v0.38 基线;增量更新至 v0.53)

本文记录 Ming 的设计哲学、关键决定与语义规范要点。变更语言行为时必须同步更新本文件与 GUIDE.md 的修订记录。

## 1. 设计哲学:明

Ming 的名字取自"明"——明确、透明、明亮。核心承诺:**程序的含义必须和它写出来的一模一样**。

这条承诺推导出六条原则:

1. **明确优于简洁**:任何隐式行为(转换、提升、真值化、遮蔽、捕获语义)都被禁止,或必须显式写出来。
2. **安全是默认**:危险操作要么被静态检查拦截,要么在运行时 panic(带错误码、位置、hint),绝不静默继续。
3. **确定性**:同样输入永远同样行为。Map 迭代 = 插入序;操作数求值 = 从左到右;整数溢出 = panic;`ming fmt` = 唯一权威风格。
4. **为验证循环优化**:AI 的核心工作方式是"生成 → 检查 → 修正"。诊断必须是结构化的(`--json`)、稳定的(错误码不换义)、可行动的(每条带 hint)。
5. **一种结构一个语法**:没有第二种写法,减少生成空间,降低幻觉混合概率。
6. **机器与人同读**:语法对 token 效率友好,关键字少而一致,错误信息面向"如何修改"。

## 2. 关键决定与理由

### 2.1 无 null,只有 Option
`Option[T]`(`Some` / `None`)是唯一的"可能没有"。缺失值必须被 match、`?`、`unwrap_or` 显式处理。不接受 `.is_some()` 之外的隐式解包。

### 2.2 整数语义
- 默认 `i64`;后缀(`42u8`)或标注决定宽度;不同宽度不混算,必须 `as` 或 `to_xx()`。
- 溢出、除零、移位越界 → panic(M4002/M4004)。没有"release 模式静默回绕";需要回绕语义等 v0.2 的显式 API。
- `as` 是位截断(float→int 是截断 + 饱和);`to_u8()` 等安全转换返回 `Option`。
- 内部用 BigInt 实现,无 2^53 精度陷阱。

### 2.3 值语义(最重要的决定)
赋值、传参、返回、闭包捕获、集合元素存入——**全部深拷贝**。程序里不存在两个名字共享同一可变结构:

- 消灭整类别名 bug(改了 A,B 莫名变了);
- 与多线程安全天然兼容(共享即不可能,竞争即不可能);
- 代价:大集合拷贝的性能。v0.1 选择正确性优先;路线图 v0.3+ 用写时复制(COW)消除常读路径的拷贝开销,语义不变。

### 2.4 错误是值,不是异常
可失败函数返回 `Result[T, E]` 或 `Option[T]`;`?` 做传播;`panic` 只用于不变量违反(assert、越界、溢出、unwrap 失败),并携带 Ming 层调用栈。跨函数边界没有异常。

### 2.5 可变性显式
`let mut` 才能赋值;会修改接收者的方法(`push`/`set`/`sort`...)要求接收者是可变位置;函数参数默认不可变。

### 2.6 match 必须穷尽
枚举要求全部变体,bool 要求 true/false,其他类型要求 `_` 或绑定兜底。带守卫的分支不算覆盖(守卫可能不成立)。

### 2.7 无预处理器、无语法宏(v0.1)
扩展靠:模块 + `pub`、参数化泛型、数据驱动 API。卫生宏在路线图上(必须可展开为等价 AST,不允许任意文本替换)。

### 2.8 泛型 v0.1:参数化
`fn first[T](v: Vec[T]) -> T` 运行时擦除、检查时单态化。类型参数上**没有操作**(没有 `+`、`==`、方法),需要操作等 v0.2 的 traits。这是诚实的限制,不是缺陷:没有 typeclass 之前,假装支持只会产生不可移植代码。

### 2.9 v0.2 的能力边界
标准库只有 `print` / `eprint` / `std.io.read_line`(效果 `io`)/ `std.time.now_ms`(效果 `time`)/ `std.math.*`。**没有文件系统、网络、进程、随机数**。v0.2 的效果系统(2.13)建立后,后续版本以 capability 方式逐项开放,保持"副作用可静态审计"的性质。

### 2.13 效果系统(v0.2)
副作用必须显式声明并逐层传播:`fn f() with io, time { ... }`。

- 调用带效果的函数时,调用方必须声明超集效果,否则 M3029。纯函数(无 with)是编译期可证明的无副作用单元。
- 效果是**编译期标签**,零运行时开销;它与未来 capability 系统的关系:effect 是"这个函数会做什么"的静态陈述,capability 是"允许它做"的运行时凭据(v0.4)。
- 已知限制(有意):闭包效果在创建处检查,存入数据结构的闭包暂不追踪调用点;`main` 声明自身效果,`test` 块拥有全部效果(验证脚手架)。
- 设计取向:宁可有传播税,也不要"默认纯但随时可能偷偷 IO"的世界。AI 生成代码最大的隐患之一就是无法从签名判断副作用。

### 2.14 trait 与 impl(v0.2)
- **方法必须定义在 trait 的 impl 中**:`trait Eq { fn eq(self, other: Self) -> bool; }` + `impl Eq for Point { fn eq(self, other: Self) -> bool { ... } }`。没有散装方法——每个方法都属于可命名接口,泛型 bound 才有依据。
- prelude 内置 `Eq` / `ToStr`,原始类型自动实现;用户 struct/enum 通过 impl 获得。
- 泛型 bound `[T: Eq]` 在**调用处**校验(单态化前的约束检查);bound 声明的 trait 方法在泛型体内可用,运行时按接收者具体类型分派(静态注册,无虚表)。
- `mut self` 需要调用方绑定 mut(与赋值规则一致);impl 的 self 可变性必须与 trait 声明一致(M3032)。
- v0.2 限制(有意):impl 只针对非泛型类型;trait 无默认方法;无 trait 对象(dyn);同类型方法名跨 trait 唯一。这些在 v0.3+ 按需开放,每一步都保持"引用可解析、分派可静态"。
- 值语义不变:方法修改 `mut self` 直接作用于接收者对象(与内置 push 一致);非 mut self 是只读视图。

### 2.15 常量(v0.2)
`const N = 10;` — 只接受常量表达式(字面量/运算/其他常量),编译期校验与循环检测;不可赋值。不做运行时初始化,保证"常量永远是真的常量"。

### 2.10 字符串
UTF-8 存储,`char_len()` / `byte_len()` 显式区分。禁止 `s[i]`(歧义),提供 `s.get(i)`(字符)、`s.chars()`、`s.slice_chars(a, b)`。插值 `"\{expr}"` 只接受可显示原始类型;结构体请用 `debug(x)`。

### 2.11 作用域与遮蔽
同层作用域禁止重复绑定(M3016);内层允许遮蔽外层。`_` 与 `_` 前缀是"故意不用"的约定。

### 2.12 语法上下文规则(仅有的两条)
1. 语句开头的 `{` 是块;表达式位置的 `{` 是 Map 字面量(`[:]` 是显式空 Map)。
2. `if` / `while` / `match` 头部与 `for` 迭代式中禁用结构体字面量(那里的 `{` 归块)。

其余语法完全上下文无关:`;` 与 `{}` 显式、无悬垂 else 问题、无运算符重载、无 `++`。

### 2.16 三期门禁模型(v0.27 立项,逐步落地)

AI 参与编写的代码,质量门禁设在三个时点,各司其职:

1. **编译期门禁(已实现,v0.27)**——语法/类型/穷尽性检查 + **效果系统即对象能力**:副作用必须写进签名(`with io, net`),M3029 强制传播,纯函数可静态证明。这是语言的硬边界:无法把带效果函数"重新分类"为普通代码——签名差异机械可见,治理只能通过签名变更(可 review)完成,不存在绕过。
2. **合并期门禁(部分实现)**——回归测试锁定语义(当前 349 项,双引擎黄金对等);**待做**:模糊测试(诊断器不 panic 不挂)、形式化验证(类型系统/效果传播的机器可查证明)。原则:语义变更必须带测试,测试即规格。
3. **发布期门禁(部分实现,v0.32 扩充)**——WASM 分层天然沙箱(线性内存,无导入即无副作用);`maxSteps`/超时熔断已实现;v0.32 新增内存配额(`--max-alloc`,累计分配口径,M4011)与墙钟熔断(`--max-ms`,M4012),均穿透子任务。**附带制度教训**:v0.32 考古发现 wasm 层自 v0.23 起从未真正实例化(11 层静默回落根因,详见 GUIDE v0.32 修订记录)——"输出正确"不等于"该层在跑",存活断言(实例化非空 + 经 wasm 导出的金标准)自此进入回归。**待做**:动态权限收回(运行中降权)、按任务粒度的资源配额。

设计立场:门禁不是事后过滤,而是**让危险代码在写作时就不合法**。编译期优先——能在静态拦截的绝不留给运行时;运行时熔断只兜"静态不可判定"的部分(死循环、资源耗尽)。

## 3. 工具链协议

### 3.1 诊断
`Diagnostic = { code, name, severity, message, file, line, col, endLine, endCol, hint?, notes? }`。错误码稳定:M1xxx 词法、M2xxx 语法、M3xxx 类型/语义、M4xxx 运行时、W3xxx 警告。见 docs/diagnostics.md。

### 3.2 命令与退出码
- `run` / `check` / `test` / `fmt` / `doc`,均支持 `--json`。
- 退出码:0 成功;1 有诊断;101 panic;2 工具链内部错误(视为 bug)。`main -> i64` 可自定义退出码。
- `run --json` 把程序 stdout/stderr 捕获进 JSON,便于工具化对比。

### 3.3 风格
`ming fmt` 输出即唯一风格:4 空格缩进、`;` 显式、注释瀑布保留、块内空行保留(至多一个)。`--check` 用于 CI。

## 4. 非目标(v0.1)

- 不追求解释器性能(路线图 VM / 原生后端)。
- 不支持并发(确定性优先;结构化并发在 v0.4)。
- 不做面向对象继承;组合 + 枚举 + match 覆盖。
- 不做隐式 anything。

## 5. 版本化

语言语义遵循 semver:破坏性变更升 minor(v0.x 阶段),修复升 patch。每次修订必须:更新 GUIDE.md 修订记录、同步 design.md 与 diagnostics.md、补回归测试。

## 6. 长期愿景:安全工具之北(v0.34 立项)

用户为 Ming 设定远期定位:**面向安全/逆向场景的工具语言**。六大支柱与 Ming 的映射、冲突及差异化答案如下——远期参考,逐版对齐,不冒进承诺。

### 6.1 二进制处理与内存控制
- **字节序/位运算/字节流**:✅ 方向契合。Ming 的 checked 整数 + Vec[u8](v0.31)+ 显式转换哲学,天然适合**显式字节序 API**(be/le 读写函数,拒绝 C 的隐式端序)。位运算已内置(checked 语义)。
- **结构体布局/packing**:远期。方案:显式属性(`#[repr(packed(N))]` 风格)符合"明确优于隐式";当前结构体无布局保证,解析二进制走显式 unpack 函数。
- **受控不安全指针/类型双关**:**Ming 的效果系统就是泛化的 unsafe 块**——危险操作不藏在语言语义里,而是进签名(`with unsafe`/`with ffi`)、可 grep、可 review。指针运算/类型双关将以此形态落地,而非自由指针。
- **零拷贝切片**:⚠️ 与值语义(处处深拷贝)直接冲突。折中方案:只读借用视图(不破坏确定性)或 scoped 线性借用;属原生后端阶段的设计课题。

### 6.2 原生系统交互
- **FFI / 内联汇编 / 直接 syscall**:载体是原生后端(C 转译/编译)。哲学约束:全部经 capability 门禁(`with ffi`/`with unsafe`),签名可见——与免杀等对抗场景的"工具用户自由"不冲突:门禁管的是**工具自身的内存安全**,不限制工具对目标系统的操作。
- 部署形态中期方案:wasm 单文件产物(无依赖,Node/浏览器可跑);静态原生二进制随 C 后端跟进。

### 6.3 海量并发网络
- 现状 worker-per-task 不适合几十万连接。远期:async/green-thread 运行时(与确定性语义的调和是设计难点)。
- L2/L3 原始包构造/嗅探:std.net 扩展 + `with net` capability,原生后端之后。

### 6.4 动态执行与文本处理
- **eval/热重载**:Ming 有独特优势——解释器/VM 即 JS 库,`eval` 可作为显式能力(`with eval`)落地,成本远低于多数语言。正则作用于字节流(Vec[u8] 版 std.re):近中期。
- 模式匹配已有(match 穷尽);字节流模式匹配随后。

### 6.5 交叉编译与部署(v0.37 预研结论)
- **实测**:运行时闭包 = 8 个模块(checker/compiler/interp/vm/wasm/lexer/parser/diag)共 **467 KB**(12,116 行);`.ming` 程序编译产物为字节码 JSON(轻量)。
- **决策(v0.38 实现)**:`ming build app.ming` 产物 = **dist 目录**(app.bytecode.json + 8 个运行时模块拷贝 + launcher.mjs)——目录形式零打包器风险,Node ≥ 18 即跑,零依赖。单文件 bundle(手写 ESM 拼接器,把 8 个文件的相对导入封闭集转换为注册表)推迟到有真实需求时——467 KB 单文件技术可行,但拼接器是新的维护面。
- **远期**:C 后端 → 交叉编译静态二进制(Go 式部署);wasm 产物(浏览器/wasmtime)作为中间形态已具备(编译器已有 wasm 后端)。

### 6.6 密码学与对抗
- **密码学原语(v0.34 起)**:std.crypto 经 node:crypto 桥接(Hash 先行,AES/RSA/国密随后),capability `crypto` 门禁。
- 反反编译/剥离符号:作为 `ming build` 的构建选项处理(不进语言语义,与"机器与人同读"不冲突)。

### 6.7 形态定位
**Python 的皮**(解释执行/REPL/脚本化)+ **C 的骨**(经受控 unsafe 的内存与寄存器)+ **Go 的腿**(并发与部署)+ **Rust 的安全带**(效果系统即默认安全带,危险时显式解绑)。差异化主张:安全能力不牺牲明确性——**每个危险操作都是签名里的一行字**。

### 6.8 原生后端(C)
- **关键洞察:wasm 资格分析可直接复用**——`isEligibleShape` + 不动点回退分析(纯数值/字符串函数、调用闭包内一致)已经解决了"哪些函数可原生编译"的判定;C 后端第一阶段 = 同一 eligible 集合,发射 C 而非 wasm 字节码。重复使用 = 零新判定逻辑。
- **映射表(设计草案)**:Ming 函数 → C 函数(static;i64 = long long,checked 运算用 __builtin_add_overflow 系列);Vec 线性布局 [len][cap][elems](wasm 已定义,直接沿用);str → 结构体(指针 + 长度,UTF-8);panic → setjmp/longjmp 或错误码返回;效果(io/fs)→ C stdio;spawn → 暂不(wasm 同样不支持的形态)。
- **门禁不变**:C 路径产出的程序仍受效果系统约束(签名不变);`with unsafe`/`with ffi` 是 C 后端之后的扩展面(指针运算/内联汇编/syscall)。
- **里程碑草案**:C1 = eligible 数值函数 → C + GCC -O2 基准(对标 wasm 提速);C2 = str/Vec 全形态;C3 = 交叉编译(-static,-target 交叉工具链);C4 = `with ffi`(dlopen)/`with unsafe`(受限指针块)。
- **C1 落地(v0.39)**:`ming cc <file> [--emit-c] [--out 目录]`——numericOnly 资格分析(`analyzeEligibility`,与 wasm 单一事实来源)+ 整程序 AOT(main 限定"AOT 形态":数值语句 + 对 eligible 函数的调用 + `print(str(整数))`/字面量串)。panic 逐字对齐:eligible 函数内用 wasm 层通用消息,main 内用 binopValues 具体消息(含操作数);诊断首行 = formatDiag 非 TTY 格式,退出码 101;stdout/stderr 二进制模式(关 CRLF)。基准:纯 sum/fib 场景 cc 比 wasm 提速约 10x。**C1 明确不做(C2)**:str/Vec/Map 传参、容器 for-in、float→int 截断、f64 的 print/diag(JS 最短往返格式与 printf 无法逐字保证)、std.math 仅位级精确子集(sqrt/fabs/floor/ceil/fmin/fmax;round 按 JS 语义 = floor(x+0.5) 单独实现)。C 产物无 --max-steps/--max-ms 熔断。
- **C3 落地(v0.41)**:Map[str,i64](插入序线性表;值语义深拷贝;M4007 逐字对齐;set/has/get/delete/for-in(k,v))+ Option[i64](Some/None/unwrap M4006/unwrap_or/is_some/is_none;Vec.pop/get → Option)+ float→int 饱和截断(ming_f2i_sat/ming_f2u_sat)+ f64 打印(ming_float_str = interp floatStr + JS Number::toString 格式化)+ str trim 族/starts/ends。**cc 差分腿覆盖 v0.41 已声明形态**(四种子 100%;仍不承诺解释引擎全部形态)。**C4 剩余**:插值串、Result 形态、keys/values/items、to_upper/lower(Unicode)、交叉编译 -static、f64 打印的极端 tie 情形(|x| > 9e14 的 toFixed 边界,文档声明)。**后续更新**:v0.42/v0.43 落地 extern fn FFI、Result[i64,str] 与同平台 `--static`;v0.53 补齐 `str` for-in(UTF-8 码点);仍未覆盖插值串、结构体/数组 FFI ABI、跨 OS 交叉编译。
- **C2 落地(v0.40)**:str(`ming_str{p,n}`,UTF-8 字节不可变缓冲;cat/eq/cmp/char_len/contains/replace/slice_chars/pad;字面量八进制转义数组)与 Vec[i64](`ming_vec{d,n,cap}`,malloc 增长;**值语义 = let/赋值/mut 传参一律深拷贝**,下标 OOB M4003 逐字对齐;push/reverse/contains/len;for-in)+ match(整数字面量臂 ± guard → if/else 链)。**C3 剩余**:Map、str for-in/trim/to_upper 族(Unicode 语义)、f64 打印(Ryū 最短往返)、float→int 截断、Option 形态(pop/unwrap)、交叉编译。(v0.51.3 trim 族、v0.53 str for-in 已补齐;其余仍按 C4/Backlog 状态。)

### 6.9 `with ffi` 设计(v0.39 定稿,C4 兑现)
- **效果即门禁**:`ffi` 为预留效果名——v0.39 不开放(M3030 仍拒绝,避免半开状态)。未来任何外部符号调用都必须带 `with ffi` 并沿调用链显式传播;无 ffi 效果的函数在类型层不可能触达 FFI,与 io/fs/net 同一套门禁语义。effectful 函数永不进 wasm/C eligible(资格分析在 `sig.effects` 处拒绝)——FFI 与原生后端天然互斥,不会出现"被 AOT 编译的函数偷偷调用外部符号"。
- **声明形态(签名即文档)**:`use std.ffi;` + `std.ffi.load("名称") -> Result[Lib, str]`(加载失败 = 数据驱动的 Err,不是 panic)+ `lib.fn("符号", 签名) -> Result[Fn, str]`。签名用 Ming 函数类型书写(`fn(i64, f64) -> i64`),调用点一眼可见外部边界。不做隐式绑定、不做宏生成绑定。
- **v1 类型面**:i64 / u64 / f64 / bool 按位宽直传;不透明指针 = `Ptr` 句柄类型(仅可与 `with unsafe` 的受限指针块互换,不可算术);str/Vec 待 C2(UTF-8 结构体/线性布局定稿后再映射)。
- **错误模型**:加载/查找失败 → Err(显式处理);调用本身是纯外部效果——无 panic 语义、无捕获;**目标库段错误 = 进程级终止,Ming 不捕获**(诚实声明,与 C 同一底线);新诊断码 M4013(ffi-load-failed)/ M4014(ffi-signature-invalid)预留(v0.39 未启用)。
- **后端策略(deferred)**:C 后端直接 dlopen/LoadLibrary + 按签名调用(零封送层);JS 后端经 N-API addon 或子进程桥(实现策略到 C4 再定)。
- **安全立场**:拒绝 GC 化的自动生命周期管理与句柄注册表;谁加载谁释放(显式 `lib.close()`),泄漏在签名与代码里都可见。
- **C4 兑现(v0.42,extern 声明形态)**:语法定为 `extern "库" fn 符号(参数) -> 返回;`(库可省略 = 当前进程)——符号编译期已知,AOT 友好,无需 Lib/Fn 句柄类型;运行时 `lib.fn(名, 签名)` API 延后到 ffi 面扩大时再评估。效果即门禁落地:extern 隐含 ffi 效果,调用方须声明 `with ffi`(M3029 逐层传播);extern fn 不进 wasm/C eligible(效果自动拒绝)。JS 引擎以合成桩体在运行时 M4001 诚实拒绝;C 后端 dlopen/LoadLibrary + dlsym/GetProcAddress 启动绑定,调用点直调,库/符号缺失 → M4013 退出 101(诊断码启用)。v1 签名面 = i64/u64/f64;`extern` 升级为关键字(自保留字表移出)。`ming cc --static` 同版交付(静态链接产物)。

### 6.10 `with unsafe` 受限指针块设计(v0.43 定稿,C5 实现)
- **定位**:FFI 解决"调用外部符号",unsafe 解决"直接读写内存"。二者是北星支柱 2(原生系统交互/内联汇编/直接 syscall)的最后一层,共用同一套效果门禁。
- **效果形态**:`unsafe` 为新效果名(与 ffi 同级,`with unsafe` 显式声明并逐层传播)。**块形态**优先于函数形态:`unsafe(expr) { ... }` —— 仅该块内允许指针操作;块外一切指针值不可读不可写(读取 `Ptr` 只可比空)。函数形态(`fn f() with unsafe`)保留为远期选项,首版不做——块比签名更细。
- **v1 类型面**:
  - `Ptr[mut u8]` / `Ptr[u8]`(不透明指针,带可写性;不可算术、不可与整数互转——转换只能经 `as` 的显式 unsafe 原语或在块内);
  - 块内操作(全部是效果语句,不引入运算符):`p.load()`, `p.store(x)`, `p.offset(n)`(返回新 Ptr), `p.is_null()`;
  - 与 ffi 的交集:extern 声明可返回/接受 `Ptr`(M4014 签名校验扩展)。
- **安全立场**:
  - 每个 unsafe 块 = 签名/代码里的一行字,块内不引入任何隐式行为;
  - 块内指针解引用不 panic(空指针读写 = 进程级 UB,诚实声明;可选 `--checked-ptr` 调试模式加界检查,非默认);
  - 不做 GC 化生命周期;谁分配谁释放(与 ffi 同款纪律);
  - wasm/C 资格分析对 `with unsafe` 函数整体拒绝(效果门禁一致—不安全代码永不进 AOT 快路径)。
- **与现有能力的关系**:std.bin(显式字节序)覆盖"结构化序列化"这一安全子集;unsafe 只服务于**无法被 std 面覆盖**的场景(内联汇编、mmap、驱动接口)。默认答案永远是"用 std",unsafe 是最后的出口。
- **实现优先级(C5)**:Ptr 类型与块解析 → 块内四条操作 → ffi Ptr 交集 → --checked-ptr 调试模式 → 内联汇编语法评估(远期)。

### 6.11 效果屏蔽与不安全封装(mask 方向,v0.44 定稿,实现待定)
- **问题**:Ming 的效果必须逐层传播——`fn f() with fs` 的调用方也必须声明 fs。这使"安全门面 API"无法构建:底层用锁/文件/ffi 的内部实现,对外应当是纯签名。Jenny 的 `mask [...]`(受控副作用阻断)给出了方向:允许在函数内部消化效果,不向上染色。
- **语法草案**:`mask [fs] { ... }` 块——块内可调用 fs 操作;所在函数的签名**可以不**声明 fs。块是语句位置表达式,返回值受类型检查约束。
- **健全性条件(v1,先窄后宽)**:
  1. **效果承载值不得逃逸块**:块内创建的句柄/资源(File 句柄、ffi Lib 等)不可出现在返回值、不可绑定到外层变量。判定用现有类型信息:块内新绑定的资源类变量在块结束时全部出作用域,块尾表达式类型不得含资源类型。
  2. **块内抛出的 panic 语义不变**(panic 不是效果,不受 mask 影响)。
  3. **mask 只影响声明表面,不影响求值语义**:同一程序加不加 mask,运行时行为完全一致(仅类型检查差异)——保证确定性。
  4. **未实现正式证明器前,不做"块内效果完备性"的静态证明**;mask 是开发者承担责任的显式声明,与 `with unsafe` 同级。
- **与 `with unsafe`(§6.10)的关系**:mask 是不安全代码的"安全门面"出口——`unsafe(expr) { ... }` 块可以嵌套在 `mask [unsafe]` 内;反过来说,`with unsafe` 函数也能被 `mask [unsafe]` 包装成纯接口。两者共用逃逸分析。
- **拒绝的替代方案**:自动推断(编译器猜哪些效果可以屏蔽)——违反"写出来的就是全部含义";按函数加 `mask` 属性——粒度过粗,块级更精确。
- **实现优先级**:v0.44 仅设计定稿;实现依赖逃逸分析(与 `with unsafe` 同批),在契约系统(v0.45)之后评估。
