# Ming 设计文档(v0.33)

本文记录 Ming 的设计哲学、关键决定与语义规范要点。变更语言行为时必须同步更新本文件与 GUIDE.md 的修订记录。

## 1. 设计哲学:明

Ming 的名字取自"明"——明确、透明、明亮。核心承诺:**程序的含义必须和它写出来的一模一样**。

这条承诺推导出六条原则:

1. **明确优于简洁**:任何隐式行为(转换、提升、真值化、遮蔽、捕获语义)都被禁止,或必须显式写出来。
2. **安全是默认**:危险操作要么被静态检查拦截,要么在运行时 panic(带错误码、位置、hint),绝不静默继续。
3. **确定性**:同样输入永远同样行为。Map 迭代 = 插入序;操作数求值 = 从左到右;整数溢出 = panic;`ming fmt` = 唯一权威风格。
4. **为验证循环优化**:AI 的核心工作方式是"生成 → 检查 → 修正"。诊断必须是结构化的(`--json`)、稳定的(错误码不换义)、可行动的(每条带 hint)。
5. **一种结构一个语法**:没有第二种写法,减少生成空间,降低幻觉混合概率。
6. **机器与人同读**:语法对 token 效率友好,关键字少而一致,错误信息面向"如何修改"。

## 2. 关键决定与理由

### 2.1 无 null,只有 Option
`Option[T]`(`Some` / `None`)是唯一的"可能没有"。缺失值必须被 match、`?`、`unwrap_or` 显式处理。不接受 `.is_some()` 之外的隐式解包。

### 2.2 整数语义
- 默认 `i64`;后缀(`42u8`)或标注决定宽度;不同宽度不混算,必须 `as` 或 `to_xx()`。
- 溢出、除零、移位越界 → panic(M4002/M4004)。没有"release 模式静默回绕";需要回绕语义等 v0.2 的显式 API。
- `as` 是位截断(float→int 是截断 + 饱和);`to_u8()` 等安全转换返回 `Option`。
- 内部用 BigInt 实现,无 2^53 精度陷阱。

### 2.3 值语义(最重要的决定)
赋值、传参、返回、闭包捕获、集合元素存入——**全部深拷贝**。程序里不存在两个名字共享同一可变结构:

- 消灭整类别名 bug(改了 A,B 莫名变了);
- 与多线程安全天然兼容(共享即不可能,竞争即不可能);
- 代价:大集合拷贝的性能。v0.1 选择正确性优先;路线图 v0.3+ 用写时复制(COW)消除常读路径的拷贝开销,语义不变。

### 2.4 错误是值,不是异常
可失败函数返回 `Result[T, E]` 或 `Option[T]`;`?` 做传播;`panic` 只用于不变量违反(assert、越界、溢出、unwrap 失败),并携带 Ming 层调用栈。跨函数边界没有异常。

### 2.5 可变性显式
`let mut` 才能赋值;会修改接收者的方法(`push`/`set`/`sort`...)要求接收者是可变位置;函数参数默认不可变。

### 2.6 match 必须穷尽
枚举要求全部变体,bool 要求 true/false,其他类型要求 `_` 或绑定兜底。带守卫的分支不算覆盖(守卫可能不成立)。

### 2.7 无预处理器、无语法宏(v0.1)
扩展靠:模块 + `pub`、参数化泛型、数据驱动 API。卫生宏在路线图上(必须可展开为等价 AST,不允许任意文本替换)。

### 2.8 泛型 v0.1:参数化
`fn first[T](v: Vec[T]) -> T` 运行时擦除、检查时单态化。类型参数上**没有操作**(没有 `+`、`==`、方法),需要操作等 v0.2 的 traits。这是诚实的限制,不是缺陷:没有 typeclass 之前,假装支持只会产生不可移植代码。

### 2.9 v0.2 的能力边界
标准库只有 `print` / `eprint` / `std.io.read_line`(效果 `io`)/ `std.time.now_ms`(效果 `time`)/ `std.math.*`。**没有文件系统、网络、进程、随机数**。v0.2 的效果系统(2.13)建立后,后续版本以 capability 方式逐项开放,保持"副作用可静态审计"的性质。

### 2.13 效果系统(v0.2)
副作用必须显式声明并逐层传播:`fn f() with io, time { ... }`。

- 调用带效果的函数时,调用方必须声明超集效果,否则 M3029。纯函数(无 with)是编译期可证明的无副作用单元。
- 效果是**编译期标签**,零运行时开销;它与未来 capability 系统的关系:effect 是"这个函数会做什么"的静态陈述,capability 是"允许它做"的运行时凭据(v0.4)。
- 已知限制(有意):闭包效果在创建处检查,存入数据结构的闭包暂不追踪调用点;`main` 声明自身效果,`test` 块拥有全部效果(验证脚手架)。
- 设计取向:宁可有传播税,也不要"默认纯但随时可能偷偷 IO"的世界。AI 生成代码最大的隐患之一就是无法从签名判断副作用。

### 2.14 trait 与 impl(v0.2)
- **方法必须定义在 trait 的 impl 中**:`trait Eq { fn eq(self, other: Self) -> bool; }` + `impl Eq for Point { fn eq(self, other: Self) -> bool { ... } }`。没有散装方法——每个方法都属于可命名接口,泛型 bound 才有依据。
- prelude 内置 `Eq` / `ToStr`,原始类型自动实现;用户 struct/enum 通过 impl 获得。
- 泛型 bound `[T: Eq]` 在**调用处**校验(单态化前的约束检查);bound 声明的 trait 方法在泛型体内可用,运行时按接收者具体类型分派(静态注册,无虚表)。
- `mut self` 需要调用方绑定 mut(与赋值规则一致);impl 的 self 可变性必须与 trait 声明一致(M3032)。
- v0.2 限制(有意):impl 只针对非泛型类型;trait 无默认方法;无 trait 对象(dyn);同类型方法名跨 trait 唯一。这些在 v0.3+ 按需开放,每一步都保持"引用可解析、分派可静态"。
- 值语义不变:方法修改 `mut self` 直接作用于接收者对象(与内置 push 一致);非 mut self 是只读视图。

### 2.15 常量(v0.2)
`const N = 10;` — 只接受常量表达式(字面量/运算/其他常量),编译期校验与循环检测;不可赋值。不做运行时初始化,保证"常量永远是真的常量"。

### 2.10 字符串
UTF-8 存储,`char_len()` / `byte_len()` 显式区分。禁止 `s[i]`(歧义),提供 `s.get(i)`(字符)、`s.chars()`、`s.slice_chars(a, b)`。插值 `"\{expr}"` 只接受可显示原始类型;结构体请用 `debug(x)`。

### 2.11 作用域与遮蔽
同层作用域禁止重复绑定(M3016);内层允许遮蔽外层。`_` 与 `_` 前缀是"故意不用"的约定。

### 2.12 语法上下文规则(仅有的两条)
1. 语句开头的 `{` 是块;表达式位置的 `{` 是 Map 字面量(`[:]` 是显式空 Map)。
2. `if` / `while` / `match` 头部与 `for` 迭代式中禁用结构体字面量(那里的 `{` 归块)。

其余语法完全上下文无关:`;` 与 `{}` 显式、无悬垂 else 问题、无运算符重载、无 `++`。

### 2.16 三期门禁模型(v0.27 立项,逐步落地)

AI 参与编写的代码,质量门禁设在三个时点,各司其职:

1. **编译期门禁(已实现,v0.27)**——语法/类型/穷尽性检查 + **效果系统即对象能力**:副作用必须写进签名(`with io, net`),M3029 强制传播,纯函数可静态证明。这是语言的硬边界:无法把带效果函数"重新分类"为普通代码——签名差异机械可见,治理只能通过签名变更(可 review)完成,不存在绕过。
2. **合并期门禁(部分实现)**——回归测试锁定语义(当前 349 项,双引擎黄金对等);**待做**:模糊测试(诊断器不 panic 不挂)、形式化验证(类型系统/效果传播的机器可查证明)。原则:语义变更必须带测试,测试即规格。
3. **发布期门禁(部分实现,v0.32 扩充)**——WASM 分层天然沙箱(线性内存,无导入即无副作用);`maxSteps`/超时熔断已实现;v0.32 新增内存配额(`--max-alloc`,累计分配口径,M4011)与墙钟熔断(`--max-ms`,M4012),均穿透子任务。**附带制度教训**:v0.32 考古发现 wasm 层自 v0.23 起从未真正实例化(11 层静默回落根因,详见 GUIDE v0.32 修订记录)——"输出正确"不等于"该层在跑",存活断言(实例化非空 + 经 wasm 导出的金标准)自此进入回归。**待做**:动态权限收回(运行中降权)、按任务粒度的资源配额。

设计立场:门禁不是事后过滤,而是**让危险代码在写作时就不合法**。编译期优先——能在静态拦截的绝不留给运行时;运行时熔断只兜"静态不可判定"的部分(死循环、资源耗尽)。

## 3. 工具链协议

### 3.1 诊断
`Diagnostic = { code, name, severity, message, file, line, col, endLine, endCol, hint?, notes? }`。错误码稳定:M1xxx 词法、M2xxx 语法、M3xxx 类型/语义、M4xxx 运行时、W3xxx 警告。见 docs/diagnostics.md。

### 3.2 命令与退出码
- `run` / `check` / `test` / `fmt` / `doc`,均支持 `--json`。
- 退出码:0 成功;1 有诊断;101 panic;2 工具链内部错误(视为 bug)。`main -> i64` 可自定义退出码。
- `run --json` 把程序 stdout/stderr 捕获进 JSON,便于工具化对比。

### 3.3 风格
`ming fmt` 输出即唯一风格:4 空格缩进、`;` 显式、注释瀑布保留、块内空行保留(至多一个)。`--check` 用于 CI。

## 4. 非目标(v0.1)

- 不追求解释器性能(路线图 VM / 原生后端)。
- 不支持并发(确定性优先;结构化并发在 v0.4)。
- 不做面向对象继承;组合 + 枚举 + match 覆盖。
- 不做隐式 anything。

## 5. 版本化

语言语义遵循 semver:破坏性变更升 minor(v0.x 阶段),修复升 patch。每次修订必须:更新 GUIDE.md 修订记录、同步 design.md 与 diagnostics.md、补回归测试。
