## 1. 目的与承诺定义

### 1.1 目的

本文件是 **T2.4 1.0-rc 准入的前置文档**(plan §4.15.2:"T2.3 稳定性契约草案,前置 T2.2,验收 = 契约评审通过")。它做两件事:

1. **划边界**:定义 1.0 起 Ming 对用户的兼容性承诺——哪些面"承诺 = 下一个 major 前不破坏",哪些面"如实声明不保护"。
2. **给流程**:破坏承诺面必须走 §4 弃用流程;非承诺面的变更仍须遵守既有工程纪律(登记/审查/回归),只是不需要迁移期。

Ming 的目标用户(生成式 AI 与人类协作,design.md §1)对"稳定"的依赖形态与人类项目不同:**AI 按文档生成代码,诊断码是修正回路的协议**——因此本契约把"诊断码不改号"与"panic 首行合同"提到与语法同等的一级承诺位(plan §4.15.3 T2.3 原文口径)。

### 1.2 承诺的定义

- **"承诺" = 下一个 major 前不破坏**。具体判据:**按现行 GUIDE 与 diagnostics.md 写出的合法程序,其可观察行为不改变**;**消费既有协议(stdout/`--json`/AOT dist/LSP 帧格式)的外部程序不需要修改**。
- "可观察行为" = 程序输出(stdout/stderr 首行)、退出码、panic 首行、诊断码、`--json` 字段集与键名、AOT 产物 wire 结构。**不含**:性能、内存占用、诊断消息的完整措辞、工具链内部实现细节(§3)。
- **"破坏"的反例**(不算破坏,走普通 minor):新增语言面(增加合法程序集合 = additive);新增诊断码;`--json` **新增**字段(既有字段集不变,additive 先例:run `wasm_status` v0.53、build 字段族 v0.53、诊断 `fix` 字段 v0.80);新增 `ming tools` 子命令;修复 §5.1 已知缺陷并附最小复现 + 零校准审计(行为变化但原行为是登记缺陷——**修复缺陷不算破坏承诺,但必须走登记纪律**)。

### 1.3 版本语义

- 1.0 前(v0.x):semver 宽松执行;破坏性变更允许,但**必须走 §4 流程**(plan 登记 + 审查 + 零校准 + GUIDE 修订记录)。
- 1.0 起:**承诺面内不破坏**;minor 版本允许 additive 增量与缺陷修复;major(2.0)是唯一重开承诺面的窗口。
- 版本号三处同步(package.json / bin/ming.js VERSION / GUIDE §24 修订记录)是既有 CI 硬门(tests/docs_check.mjs 校验项 1——版本漂移即红,先例:2026-11-20 首跑抓到 README 三处预存漂移)。

## 4. 弃用与破坏性变更流程

1. **常规路径**:弃用警告 ≥1 个 minor → 移除。警告必须具名(诊断/`--json` 字段/stderr 提示 + GUIDE §24 修订记录条目),给出迁移处方。minor 期间新旧并存(如新签名 + 旧签名各带 M/W 提示)。
2. **安全修复例外**:安全缺陷(如洗白旁路、注入面)可不警告直接修——修复不得静默:**必须 plan 登记 + 最小复现 + 零校准审计**。先例:污点系统三次破坏窗口(v0.61 extern 返回强制/v0.68 serve 翻转/v0.82 argv)均走了"登记 + 审查 + 迁移 52 命令逐字节对照"的完整流程;1.0 起同型安全修复走同流程,只是不再承诺给迁移期。
3. **每次破坏性变更的三件套**(沿 AGENTS §6/§7 硬规则):plan 登记(登记在 §5.1 缺陷表或 §4.x 任务行)+ 独立审查(每批独立审查硬线,plan §4.17.5 纪律 2)+ 零校准审计(既有断言因行为变化而修改的,逐条给出行为变化理由——"零校准"指不因重构而校准,语义变化必须显式)。
4. **诊断码特殊纪律**:已发布码永不复用(§2 P4);废弃码保留号段(M3047 先例);**弃用诊断码**时码保持发射但语义降级为"不再触发于新代码",码表登记废弃。
5. **冻结期约束**:T2.2 冻结令生效后,冻结面(语法/关键字/类型面/效果名/诊断码族/内置函数)不新增(plan §4.15.3 T2.2);本契约在其之上管 1.0 后的**用户兼容**——冻结令管开发期,契约管发布后。

## 7. 诚实边界

1. **契约 = 意图声明 + 现状快照**。每项承诺引用的证据(文件+符号/分节+行号)是 HEAD `15cf7f8`(2026-11-21)的现状;行号必然漂移,稳定锚是"文件 + 符号名/测试分节名"。证据的有效性由既有机器门背书:全量回归(tests/run.mjs 分节 §1–§111)/fuzz 差分/tests/opt_gate.mjs/tests/support_matrix/run.mjs/tests/docs_check.mjs。
2. **契约不承诺"未来不引入新承诺"**。本文件只划下限(§2)与豁免面(§3);1.0 后新增的语言面一经发布**自动进入承诺面**(additive 先例字段/形态,下次破坏同样走 §4)——无需修订本文件;修订本文件不等于变更承诺,变更承诺 = §4 流程 + 版本事件。
3. **本文件不冻结任何东西**。冻结令(T2.2)是维护者的独立确认;草案先行的意义是让"冻结什么、承诺什么"在确认时**已有文本可裁决**,而不是让文档先行造成既成事实。
4. **覆盖率缺口如实登记**:P5 的 `--json` schema 各命令键集尚未有逐命令快照测试(现有测试覆盖 run wasm_status/build 字段/doc schema;check --json 的 proofs/warnings 结构有测试但没有逐键冻结)——1.0-rc 准入(T2.4)建议补"协议快照测试"作为准入项,本草案不预支实现。
5. **与本仓库文档的关系**:本文件是承诺的**汇总视图**,不是单一事实来源——各面的单一事实来源仍是其依据文件(GUIDE/diagnostics.md/checker.js/artifact.js/bin/ming.js);本文件与其依据文件冲突时,以依据文件为准并视为本文件的缺陷(登记 plan §5.1)。
