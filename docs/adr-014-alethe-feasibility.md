# ADR-014:S-3「Alethe 证明日志」可行性预研——Ming 自己能产出什么可独立复核的证明对象

> **立场声明**:本 ADR 是**纯文档交付**——零 src/tests/既有 docs 改动,不写任何实现代码(ADR-003-mask/005/006/012 同款纪律)。**外部事实**(Alethe / cvc5 / carcara 的格式、旗标、版本、规则覆盖)一律按公开知识描述并**逐条标注置信度**,凡不确定即标"待核实",不写版本号、不编旗标拼写。**仓库事实**以"文件 + 符号/分节"为稳定锚(行号仅为快照辅助)。
> **结论先行**:**S-3 的原措辞不能由 Ming 自己兑现,但可以被兑现——且能用比 Alethe 更强的对象兑现**(Alethe 日志可由外部求解器产出而字面兑现,证明主体换成第三方;Ming 若要自产,则取决于 U4,未核实)。四条:
> ① **当前的 Ming 证明器不能"自主"产出 Alethe**:Alethe 是**求解器**产出的、面向 **resolution/理论重写推理链**的证明格式(主要由 cvc5 系产出,由 carcara 系独立复核);而内部证明器是**差分约束 Bellman-Ford 判定器**——`src/prover.js` 头注自述其职责为"线性形式代数 + 差分约束求解…+ 蕴含判定"(只答"成立/不成立/放弃",不构造推导),`solveDiffConstraints` 的返回面只有 `{kind, cycle}`(环上变量名,信息性)。`--proof-format alethe` 因此有**三条路**(§2.3):**①转调外部求解器**(作者 = cvc5;今日即可兑现 roadmap 字面语义,但证明的主体换人);**②把负环的 Farkas 系数渲染为合法的 Alethe 算术规则步**——这是唯一可能让 Ming **自产** Alethe 的路径(不换算法,只多一个渲染层),可行性 = U4(**未核实**,列为观察项);**③伪造/近似文本**(拒绝)。
> ② **Ming 能产出一份真正可独立复核的对象,且判定阶段已给出它的变量证据**:对当前索引义务面的每个 `proven` 方向,内部判定的**负环**本身就是一份**系数为 1 的线性不可满足证书(Farkas 型)**;验证判据 = 纯 BigInt 的"每条引用约束规范为 `Σ c_i x_i <= K_i`,存在非负整数 λ 使 `Σ λ_i c_i = 0`(逐变量恒等)且 `Σ λ_i K_i < 0`"(严格不等式按整数语义归一为 `<= K−1`),任何第三方用数十行算术即可复核,**不需要求解器、不需要 Ming、不需要网络**。整数域下该证书**健全**(绝不误证),唯一代价是**不完全**(只是整数不可行的一个子集有证书——而对当前差分片段不构成缺口,§3.3)。**边/假设的出处还需由同一函数顺带记录**:`pred` 现只存节点下标,不足以定位具体断言(§3.2 末)。
> ③ **建议 S-3 重新定义为"可独立复核的证明工件"**:v1 = 自产线性证书;Alethe **降级为外部求解器旁路**(文档化配方,用户运行期自决动作,不属于 Ming 承诺面,不引入构建期依赖)。
> ④ **承诺分层**(可直接并入 proof-protocol §5):证书**判据与引用规则冻结**、**渲染实验性**、**覆盖率不承诺**、**与 Alethe 的关系非承诺**、**有效性范围非承诺**(证书只证编码后的约束集不可满足,不证编码忠实、不证运行时安全)。

## 2. 事实层:Alethe 是什么,它与我们的义务是什么关系

### 2.1 高置信事实(置信度标注)

| 事实 | 置信度 | 说明 |
|---|---|---|
| Alethe 是**面向 SMT 求解器的证明格式**,设计目标是**求解器无关**、可被**独立证明检查器**复核 | 高 | 与 SMT-LIB 同族的 s-expression 命令式语法;一次证明 = 一串 `(step …)` 步,每步带 `:rule`/`:premises`/`:args`,末步推出空子句 |

### 2.2 外部待核实清单(与 §9 合并,此处只列与本决策强相关的四条)

1. cvc5 输出 Alethe 的**确切调用面**(旗标/输出通道/是否需要每查询一份);

3. carcara 对**算术规则**的支持面与版本对应关系;
4. Alethe 规则集中是否存在可承载"**线性组合(Farkas)证书**"的单步规则(我印象中存在 `la_generic` 一类算术规则,但**参数形状不确定**——置信度低,必须实测,不得据印象设计)。

### 2.3 判定:为什么 Ming 证明器不能**自主**产出 Alethe(三条路逐一裁决)

三引擎/多后端的差分合同、SMT-LIB 导出、静态证明面,共享同一个事实:**Ming 的静态证明器是"判定器",不是"证明搜索器"**。

- `src/prover.js` 的实现是**线性形式代数 + 差分约束求解**:约束被规范化为 `D <= c`,再编码成边 `d_v - d_u <= w`,`Bellman-Ford` 在 `n` 轮内收敛 ⟺ 可满足;第 `n` 轮仍可松弛 ⟺ 负环 ⟺ 不可满足。它的输出是 `{kind:'sat'|'unsat'|'too-many-vars'}` 与一个**信息性的环上变量名列表**(`cycle`)。
- 它**没有**、也**不打算有** resolution 步、理论重写步、项重写链、子句演算——这些是 Alethe 的语法实体。要产一条 **resolution 链**,等于换一个证明算法(或调用别人的);**"把负环系数交给一条接受乘子的算术规则"是唯一不换算法的可能**,见下第 2 条。
- 因此 `--proof-format alethe` 有**三条路**,而不是两条:
  1. **转调外部求解器**(= 方案 A):证明的作者是 cvc5,不是 Ming——**roadmap 的字面语义在这一路上今日即可兑现**,只是主体换人(与 §4.1 一致);
  2. **把负环的 Farkas 系数渲染为一条合法的 Alethe 算术规则步**:若 Alethe 的算术规则接受"一组约束 + 乘子",我们的负环系数恰好就是它的输入——这条路上 Ming **不需要换证明算法,只需多一个渲染层**。**可行性完全取决于 U4**(Alethe 是否真有这样的规则、参数形状是否稳定),**置信度低、未核实**,因此只能列为观察项(S-3c),不得被当作承诺;
  3. **伪造/近似**(把负环包装成不对应任何规则的 `(step …)`):**拒绝**。理由不是"我们觉得不行",而是它属于"看起来像证明的文本"——即使外部检查器**可能**接受(此点未实测,**置信度中低**),也直接违反"程序的含义必须和它写出来的一模一样"的第一原则与 proof-protocol 的"不虚标"立场。
- **收窄后的结论**:S-3 **不能**按原措辞直接排期——它预设 Ming 有产 Alethe 的算法;但也不是"无解":(1) 是现成的转交路径,(2) 是唯一自产桥接候选且门槛未核销。**因此 S-3 的定义修正是必要的(§6.4),而不是偏好。**

### 2.4 但 roadmap 的真实目标可以兑现(问题重述)

roadmap 那句话的**目的从句**是"**使证明可被独立证明检查器复核**",Alethe 只是当时想到的**手段**。手段换成"任何可被独立复核的证明工件"后,问题变成:

> **Ming 能否对每个它声称 `proven` 的义务,产出一份不依赖 Ming 自身判定、可被第三方机械复核的凭证?**

答案是**能**:判定阶段已经给出了证书的**变量证据**(负环上的变量名),但**边的出处**(每条边来自哪条断言、哪种归一)尚未被记录,需要由同一函数顺带产出。见 §3。

## 3. 关键事实:Ming 的证明器实际产出什么(源码可核对)

### 3.1 判定机制(锚点)

| 事实 | 锚点 |
|---|---|
| 变量上限 12;超限放弃(保守) | `src/prover.js` `MAX_PROVER_VARS` |
| 约束 → `D <= c`: `<` 记 `<= -1`、`>=`/`>` 取反对称、`==` 拆双向、`!=` 不可编码(跳过) | `toLePairs` |
| 可编码性:系数必须 ±1、变量 ≤ 2(双变量须一正一负,即 `x - y` 形态);绝对约束借锚点 `SRC` 变差分 | `encodeLe` |
| 不可编码约束**被丢弃**(削弱系统 → 只会漏证,绝不误证) | `encodeLe` 返回 `'skip'` 分支 |
| 判定 = 全 0 初始化的 Bellman-Ford;第 n 轮仍可松弛 ⟺ 负环 ⟺ unsat;另记 `pred` 前驱用于**负环提取** | `solveDiffConstraints` |
| 常量事实不成立(空 LHS 的矛盾)单独记 `constFalse` | 同上 |
| `proveImplication` = 把目标取反并入假设再求解;`proven` 即"`H ∧ ¬goal` 不可满足" | `proveImplication` |
| 义务判定面:`lowOk`/`highOk`(proven)、`lowBad`/`highBad`(refuted);`eff = requires 假设 ⊕ 循环区间` | `src/checker.js` `checkIndexBoundsStatically` 第 4 步 |
| VC 记录形状(含 `assumptions`/`form`/`lenVar`/`low`/`high`)已稳定并被 SMT 导出消费 | `src/proofsmt.js` 头注 · proof-protocol §1 |

### 3.2 负环即证书(结构性论证 + 最小实例)

一条边 `u → v` 权 `w` 表示 `d_v - d_u <= w`。一条负环 `u₁ → u₂ → … → u_k → u₁`(`Σwᵢ < 0`)求和即得:

```
(d_u₂ − d_u₁) + (d_u₃ − d_u₂) + … + (d_u₁ − d_u_k) = 0  <=  Σwᵢ < 0
```

即:**这些约束以 λᵢ = 1 的非负整数线性组合恒等于 0,而右端常数之和 < 0**。这正是 Farkas 型不可满足证书的判据形态。`constFalse` 是它的退化形态(单条约束,LHS 为空)。

**最小实例**(`tests/proof_fixtures/proven.smt2` 的 low 方向块**全文**;`←证书引用` 标出该证书引用的两条,其余断言不参与本证书):

```
; 方向 low — ming 内部判定: proven(期望 unsat)
(push)
(declare-const i Int)
(declare-const len$buf Int)
(assert (>= i 0))              ← 证书引用(系数 1)归一:−i <= 0
(assert (< i len$buf))         ← 不参与本证书(它属于 high 方向)
(assert (not (>= i 0)))        ← 证书引用(系数 1)归一: i <= −1
(check-sat)
(pop)
```

两条系数 1 相加:`(−i) + (i) = 0`,`0 + (−1) = −1 < 0` → 该方向块不可满足 → `0 <= i` 在假设集下成立。**证书 = 两条引用 + 一句算术恒等式**,复核不需要任何求解器。

`high` 方向同理:该块的三条断言里,`(assert (< i len$buf))` 与 `(assert (not (< i len$buf)))` 相加得 `0 <= −1`(`(>= i 0)` 不参与)。

**但"已给出"要打折扣(实现前提)**:判定目前只返回**环上变量名**(`cycle`),不返回边;而 `pred` 存的是**节点下标**而非**边下标**——同一对节点之间可能有平行边(`==` 拆出的两条边、同一断言被多重引用),按节点对反查会**取错边**。因此实现工作项的第一条是:**`pred` 改存边下标**,并在同一次 Bellman-Ford 中记录 `{边 → (断言序号, 归一方向)}`。这一步不做,证书就只能靠二次编码猜出来——那正是"假证书"的来源(§7 风险 1)。

### 3.3 健全性与完全性的方向(必须说准——此处易被说反)

| 命题 | 成立? | 论证 |
|---|---|---|
| 有 Farkas 证书 ⇒ 系统在**实数**上不可满足 | 是 | Farkas 引理(非负组合导出 `0 <= 负数`) |
| 系统在实数上不可满足 ⇒ 系统在**整数**上不可满足 | 是 | `ℤⁿ ⊆ ℝⁿ`(整数解即实数解;取逆否) |
| **因此**:有证书 ⇒ 整数不可满足 | **是(健全)** | 上面两条串联。**证书绝不会误证** |
| 实数可行 ⇒ 整数可行 | **否** | 反例:`2x = 1` 只有实数解 1/2。**这是不全性的来源,不是不健全性的来源** |
| 当前片段(差分约束)实数可行 ⟺ 整数可行 | 是 | 差分约束矩阵为节点-弧关联矩阵(全幺模);整数权重下最短路解本身是整数解 |
| **当前索引义务面**(目标 op 仅 `>=` 与 `<`)的 `proven` 方向都有证书(结构性预期) | 是(待实现批次实测确认) | `proven` ⟺ 编码子集不可满足 ⟺ 负环或常量矛盾 ⇒ 证书由该负环/该常量断言直接给出。**三条已知例外路径必须登记**(今日不在索引义务面上,但扩面后会撞上):`proveImplication` 的 `==` 分支返回 `cycle: []`(双向各自成立,无单一环);防御性中断返回 `cycle: []`;`constFalse` 目前只记布尔(**需同样记录"哪条断言"**才有引用可写)。**纪律:论证不等于实测,实现批次必须用语料逐条确认(AGENTS §2.4)** |

**诚实限制(必须写进协议)**:证书体系对 **QF_LIA 不完全**——整数不可行但实数可行的系统(整性间隙、整除性论证)没有 Farkas 证书。当前不影响我们,因为内部证明器只在差分片段内声称 `proven`;但**一旦证明面扩面**(一般 LIA / 整除性 / 委派外部求解器),`proven` 集合可能超出"实数不可行核",证书覆盖率会下降——这必须是**登记在案的非承诺项**(§6.3),不得事后解释成缺陷。

> **一处必须说准的措辞**:业界常见表述是"Farkas 对整数域不健全"——精确地说,**证书本身对整数健全**(它只证"更弱的实数系统也不可满足");不健全的是反方向推理:"实数松弛**可行** ⇒ 整数**可满足**"以及"实数可行即整数可行"。证书只走"不可行 ⇒ 不可行"的方向,因此可用;代价只落在**完全性**上(见上)。

### 3.4 归一规则与边界形态(判据必须钉死的形态表)

| 形态 | 归一(整数语义) | 说明 |
|---|---|---|
| `(<= a b)` | `a − b <= 0` | 原样 |
| `(< a b)` | `a − b <= −1` | **依赖整数域**;这是判据的一部分,必须在规范里逐字写明 |
| `(>= a b)` / `(> a b)` | `b − a <= 0` / `b − a <= −1` | 取反对称 |
| `(= a b)` | 双向两条,引用时须具名方向 | 与 `toLePairs` 一致 |
| `(assert (not G))` | 先消去 `not`(本协议中 `G` 只含 `>=`/`<`,否定即对偶比较符),再归一 | 脚本结构保证(`src/proofsmt.js` `renderDirection`) |
| 同一假设被引用多次 | 允许（多重集，λ 可 > 1；本实现因简单负环 λ 恒 1） | `==` 拆双向后同一假设贡献两条边——两条边互为反向且常数和恰为 **0**（权 0 二环），**不可能同处负环**（实现审查 MINOR-1 修正：旧措辞"可能同时入环"不准确，20000 系统 λ 核查 0 例外）；`!=`/重复断言等的多重引用面由判据的 λ 语义覆盖 |
| 常量矛盾 | 单条引用,LHS 为空 | `constFalse` 退化形态 |

**vacuity 边界(必须如实标注——且不能用"证书是否引用目标行"来判定)**:

- **两种来源**:(a) `requires` 与循环区间互相矛盾(`eff` 不可满足);(b) **空区间**——`for k in 0..0` 的区间约束(`0 <= i$n` 与 `i$n < 0`)自身即矛盾,**不需要 `requires` 有任何矛盾**,循环体一次都不执行,而义务仍记为 `proven`(实测形态:`requires buf.len() >= 0` + `for k in 0..0` → 两方向 proven)。
- **判定方法**:真空判定 = 对 **`eff`(requires + 循环区间,不含取反目标)再做一次 `solveDiffConstraints`**;不可满足 ⇒ `vacuous: true`。只有 `scope: loop` 需要这一次(直线体在第 2 步已保证 `eff` 可满足),成本 = 每义务一次差分求解(变量 ≤ 12,可忽略)。
- **`uses_goal` 不是真空检测器**:负环提取沿前驱链**任选一个**环;即使 `eff` 自身不可满足,选中的环也可能恰好包含取反目标那条边(实测形态:`requires a >= b && a >= 1` + `for k in a..b`,low 方向的环为 `["i$0","a"]`、含目标边,而义务仍真空)。因此证书须携带**两个互相独立**的字段:`uses_goal`(**纯证书属性** = 本证书是否引用取反目标行)与 `vacuous`(**第二次求解的结论**)。**若暂不实现第二次求解,措辞必须收窄为**:`uses_goal=false` 可**证明**真空;`uses_goal=true` **不能证明**非真空。
- **语义**:真空 `proven` 不是缺陷(该路径上不变式确实不承担义务),但**不得被汇报成"边界已证"**;`vacuous: true` 是给读者的诚实标注,不是新语义。

## 4. 可行性矩阵(三方案)

### 4.1 方案 A:外部求解器产证明(Ming 只发 VC + 调用/交付日志)

**形态**:`ming check --proof-format smt-lib` 已有;新增(可选、运行期、用户自决)以证明模式调用 cvc5,把 Alethe 日志与 `.smt2` 一起交付;Ming 自身零证明生产。

| 维度 | 评估 |
|---|---|
| 承诺面 | "证明由 **cvc5** 产生,可被 **carcara** 复核"——作者是求解器,不是 Ming。路线图原句"使证明可被独立证明检查器复核"在**字面**上兑现,但**主体换人** |
| 构建期依赖 | **禁止**(仓库硬规则:零第三方依赖、Node ≥18 零 npm)。因此只能做成**文档化配方 + 用户手动执行**,不得进入 `build`/CI/工具链 |
| 结构性摩擦 | 我们的脚本是**多 `push/pop` × 多 `(check-sat)`**(每义务两方向)。Alethe 证明是**每查询一份**的形态,「证明↔义务」的对应关系需要拆分脚本或依赖求解器的多次输出约定——**待核实**;**若这条旁路必须改变该旗标默认输出结构**才成立,则与 proof-protocol §3.1 **冻结**的结构不变式冲突(因此旁路只能是另一个旗标/另一份文件,不得改默认输出) |
| 确定性/可复现 | 差。证明文本随求解器版本/选项漂移;入库会形成大体积、不可审阅的工件(与 R-19"fixture 即 diff"的纪律相反) |
| 主要风险 | (i) QF_LIA 的 Alethe 证明可能含洞/不可检(算术是重灾区);(ii) 版本漂移使历史工件失效;(iii) 我们无法对"可检"作任何承诺,却会被读成承诺;(iv) 消费者要求 Ming 交付证明时,交付的其实是"某个 cvc5 版本的行为快照" |
| 成本(估) | 代码近零(最多一个薄封装/文档);**认知与维护成本高**(每次"为什么我的 cvc5 检查不过"都要由我们承担解释成本) |
| 承诺强度 | **弱**(对象有效性完全外置) |

### 4.2 方案 B:Farkas 型证书(自产)——**推荐的实质路径**

**形态**:新增 `--proof-format cert`(或 `--proof-cert`),对**当前索引义务面**的每个 `proven` 方向输出证书:引用 `.smt2` 同方向块内的约束(或直接内嵌归一后的约束行)+ 非负整数系数 + 恒等式核对值。Ming **自己生产**、**自己可被第三方复核**、零外部依赖。

| 维度 | 评估 |
|---|---|
| 承诺面 | "**Ming 产出一份可独立复核的证明工件**:对该义务编码后的约束集(每条规范为 `Σ c_i x_i <= K_i`),存在非负整数 λ 使 `Σ λ_i c_i = 0`(逐变量恒等)且 `Σ λ_i K_i < 0` → 整数域不可满足 → 目标在假设集下成立"。作者 = Ming,复核者 = 任何第三方 |
| 与 Alethe 的关系 | **不是 Alethe**。不冒充、不包装成 `(step …)`。若要接 Alethe 生态,只有 §2.2 第 4 条(算术规则承载线性证书)成立后才有讨论空间——作为**未来观察项**,不入本批 |
| 构建期/运行期依赖 | **零**。生产端 = 纯格式转换(与 `src/proofsmt.js` 同族);复核端 = 数十行 BigInt 算术(参考检查器放 `tests/`,是开发期脚本,不是构建依赖) |
| 确定性/可复现 | 强。证书内容由负环决定,而**输出按假设采集序排序**(环的遍历序只作内部中间量);可由 fixture 逐字节锁定(R-19 先例) |
| 主要风险 | (i) **归因簿记**出错会产出**错误证书**(比没有更糟)——必须单一事实来源:记录边→假设的出处,禁止在证书模块里二次实现编码规则(duplicated encoding = drift = 假证书);(ii) 受信基座不变(§5.5);(iii) 覆盖率随证明面扩面下降(§3.3,已登记为非承诺) |
| 成本(估) | src ≈ **170–280 行**(`prover` 边出处记录 + 证书渲染 + checker 附证 + `bin` 旗标/`--json` 字段;分解见 §8),测试 ≈ 新增一分节 + fixtures,文档 ≈ proof-protocol 新节 + 三处行修订 |
| 承诺强度 | **强**(对象可机械复核、判据可冻结、无版本漂移) |

**为什么"负环即证书"是干净的实现路径**(与仓库纪律的对应):判定的单一事实来源是 `solveDiffConstraints`;证书必须由**同一个函数**在同一次求解中顺带产出(边列表 + 前驱边),而不是另写一份编码器。这样"证书说不可满足"与"判定说 proven"在构造上不可能不一致——**两者是同一个计算的两个视图**。

### 4.3 方案 C:维持现状 + 增强 provenance

**形态**:不做证明日志;承诺面 = "VC + 可被外部求解器复核 + provenance manifest(源文件/工具链哈希随工件)"。

| 维度 | 评估 |
|---|---|
| 承诺面 | "你可以拿我们的 VC 去任何求解器复核"——已经是事实(proof-protocol §6),无新增 |
| 成本 | 最低(纯文档 + 在途 provenance 工作) |
| 风险 | 最低 |
| 承诺强度 | **最弱**。S-3 从"输出证明工件"退化为"我们仍然只是导出 VC";roadmap 那句"可被独立**证明检查器**复核"仍未兑现(外部求解器复核的是 **VC 结论**,不是**证明**) |
| 诚实性 | 高——但使得"S-3"这一项事实上被删除,需要在 `docs/roadmap-infrastructure.md`/plan 里如实登记为"降级/移出",不能静默消失 |

## 5. 架构吻合度

### 5.1 证明只报告、不改语义(proof-protocol §7 的口径)

证书是**纯输出选项**:不改变 `proven`/`refuted`/`unknown` 的任何判定,不改变 M3045/W3105 的发射,不改变退出码,不改变 `--json` 既有字段(只**新增**)。这与 S-1 的先例完全同构(proof-protocol §4.4:"SMT 导出是纯输出选项,不改变任何判定"),也符合 stability-contract §1.2 的 additive 定义。**同时重申既有口径**——proof-protocol §7 原文:"证明只报告,不改运行时语义(M4003 边界 panic 原样保留)":`proven` 不消除运行时 M4003,证书也不改变这一点——证书证明的是"编码后的约束集不可满足",不是"程序不会 panic"。

> **编号注(既有冲突,本 ADR 不改号)**:仓库内该口径以**内联编号"ADR-003"**出现在 plan §4.2.2 的 ADR 表("ADR-003 | 边界证明不消除运行时检查")与 ADR-009 正文;而文件 `docs/adr-003-mask.md` 是 **mask 裁决**,与"证明只报告"无关——plan §4.2.2 头注已声明该表编号"已被 docs/adr-00N 文件系列取代"。故本 ADR 一律引用可核对锚(**proof-protocol §7** + plan §4.2.2 表条目),不写"ADR-003"。

### 5.2 确定性与 fixture 纪律(R-19 先例)

证书文本必须**逐字节确定**:无时间戳、无绝对路径、无随机顺序。**引用列表按假设采集序排序**后输出(确定性);环的遍历序(前驱链序)只是内部中间量,**不得直接决定文本顺序**——否则同一判定换一个起点就会产出不同字节。字节确定性由 fixture 锁定(建议 `tests/cert_fixtures/`,与 `tests/proof_fixtures/` 同款:默认严格逐字节、`--update-fixtures` 为唯一更新通道、**更新即审查信号**)。这条纪律把"证书格式漂移"变成一次可见的 git diff,而不是静默行为变化。

### 5.3 零依赖:产物是纯格式转换,检查器是开发期脚本

- 生产端:`src/prover.js` 顺带记录边出处(**`pred` 改存边下标**;不引入任何外部输入)→ `src/proofcert.js`(新,与 `proofsmt.js` 同族,纯函数)渲染。
- 复核端:**规范优先**——proof-protocol 写清判据(§3.4 的归一规则 + `Σ λ_i c_i = 0 且 Σ λ_i K_i < 0`),任何语言数十行可实现;仓库内的参考检查器是 `tests/` 下的开发期脚本,不进 `ming build`/`ming cc`/工具链,不新增 npm 包。
- **不引入求解器**:证书复核不需要 z3;z3 仍只承担"独立消费 VC"的角色(proof-protocol §6)。

### 5.4 证据面互证:四个面不能互相替代

| 证据面 | 它证明什么 | 它**不**证明什么 |
|---|---|---|
| `tests/fuzz.mjs` 差分 | 多引擎**运行时**语义一致 | 静态义务的真伪 |
| 证书 + 独立检查器 | 某义务**编码后的约束集**不可满足(数学事实) | 编码是否忠实于源码;运行时安全 |
| `tests/z3_check.mjs` | 第三方求解器对同一 VC 给出**同向回答** | 我们的判定是否"有证明"(z3 只回 sat/unsat) |
| `tests/proof_fixtures/` | 输出**确定性**(说的和上次一样) | 判定正确性(fixture 通过只证"未变") |

四者叠加才构成"我们说的和做的一样";把其中任何一项说成另一项,就是 AGENTS §9"模糊器覆盖不等于语义证明"的同型错误。**特别地:不得把"z3 能复核 VC"表述成"Ming 产证明"。**

### 5.5 受信基座(证书检验不到的东西——必须明写)

证书只覆盖**数学那一步**。以下步骤**不被证书检验**,属于受信基座:

1. **AST → 线性形式**:`checker.linOfBoundExpr` 与 requires 归约(含 `||`/非线性叶子的**丢弃**——丢弃只削弱假设集,方向上安全,但"哪些被丢"不经证书);
2. **线性形式 → SMT 文本**:`src/proofsmt.js` 的渲染(保留字重写、负数一元减、`$` 符号);
3. **约束 → 引用**:证书引用的行是否真是该方向块的断言(建议由"引用即逐字文本 + 仓库内一致性测试"来钉住);
4. **源码 → 义务**:索引点采集门槛、循环区间的建立(§7 的"未采集 ≠ 已证明")。

**这正是 provenance(源文件哈希 + 工具链指纹)能补的位**——它与证书是互补而非替代:证书证数学,provenance 证"这份数学来自这份源码与这个工具链"。同日本批已落盘 **ADR-013**(`docs/adr-013-provenance-manifest.md`,草案):其 §1 末句明确"只解决出处随工件旅行,不解决证明生产(内部差分求解器不产推理链,Alethe 问题见 ADR-014)"——两份 ADR 的分工因此是**正交的**:ADR-013 给字段(工具版本 / 采集 pass 指纹 / 源哈希 / 求解器回填位),ADR-014 给"到底产什么证明对象"。落地时二者的 manifest 应合并为同一个旁车文件,但**不得**互相引用为"已实现"。ADR-013 §6 末条已预留 `solver` 位承载外部证明日志的(路径 + hash)指针——那正是方案 A 的最薄形态,与本 ADR 的 S-3b 对齐。**两点约束**:(i) `solver` 是**消费者回填位**,不是 Ming 自动填充(ADR-013 明写 `solver: null` 恒定);(ii) 若采纳方案 B,须走 **manifest v2(或 ADR-013 修订)** 增补证书指纹位(证书文件哈希 + 证书格式版本),**不得在 v1 里静默加键**——ADR-013 §4 已把"加法演进 = `manifest_format` 升版"定为规则。

## 6. 推荐

### 6.1 排序与理由

| 排序 | 方案 | 理由 |
|---|---|---|
| **1(入 plan)** | **B(自产线性证书)** | 唯一同时满足"真产出证明""零依赖""确定性""判据可冻结"的路径,且对**当前索引义务面**的 `proven` 集合**结构上**全覆盖(待实现批次实测);它兑现的是 roadmap 的**目的**,不是它的**手段**;实现路径与仓库"单一事实来源"纪律同构(证书与判定是同一次计算的两个视图) |

### 6.3 承诺措辞草案(可直接并入 proof-protocol §5 分层表)

| 面 | 状态 | 说明 |
|---|---|---|
| 证书**判据**与**引用规则**(文法/归一/恒等式/义务 id 对应) | **冻结**(自引入版) | 三件事不变:①**归一规则逐字固定**——每条引用约束规范为 `Σ c_i x_i <= K_i`,其中 `(< a b)` 归一为 `a − b <= −1`(**依赖整数语义,是本判据的一部分**),`(>= a b)`/`(> a b)` 取反对称、`(= a b)` 拆双向并具名;引用必须指向同一方向块断言面的约束;②**验证判据自包含** = 存在非负整数 λ(负环边上全为 1,同一断言可多重引用)使 `Σ λ_i c_i = 0`(逐变量恒等)且 `Σ λ_i K_i < 0`;③`vc:<fn>:<n>` 与证书段的对应规则不变 |
| 证书**文本渲染**(排版/字段序/注释/标注位) | **实验性** | 与 SMT 脚本注释同款:外部消费者应解析结构,不应比较排版;引用列表按假设采集序排序输出(确定性);字节确定性由 fixtures 锁定(R-19 先例),`--update-fixtures` 为唯一更新通道 |
| 证书对 `proven` 集合的**覆盖率** | **不承诺** | 只覆盖"实数不可行核",**覆盖范围以本协议为准**;证明面扩面后可能出现无证书的 `proven`(具名跳过,不伪装、不静默)。§3.3 列出的三条无单一负环路径(`==` 目标 / 防御性中断 / 仅 `constFalse` 布尔)在扩面时**必须先补出处记录**,不得直接宣称覆盖 |
| 证书的**有效性范围** | **不承诺** | 只证"该义务按协议编码后的约束集不可满足";**不含** (i) AST→约束的忠实性、(ii) 运行时安全(proof-protocol §7:proven 不消除 M4003)、(iii) 程序整体正确性 |
| 与 **Alethe** 的关系 | **非承诺** | Ming 不产出、不校验 Alethe;外部求解器证明日志是**由用户发起**的运行期动作(S-3b 配方,§6.2/§6.4),不进入构建链、不进入 CI 门槛 |
| 本协议是否纳入 P1–P8 承诺面 | **未纳入**(沿现状) | 新增面按 stability-contract §1.2 走 additive;纳入承诺面须契约修订 |

## 7. 风险与缓解

| # | 风险 | 级别 | 缓解 |
|---|---|---|---|
| 1 | **归因簿记错误 → 假证书**(比没有证书更糟) | 高 | 证书与判定同源同计算(`solveDiffConstraints` 同次求解顺带产边出处);**`pred` 必须存边下标**(节点下标无法区分平行边);禁止二次实现编码;参考检查器对每份证书**重算**恒等式,不信任声明的系数;负例测试三形态(篡改/越块引用/漏引用) |
| 2 | 证书被读成"程序正确性证明" | 中高 | 承诺表第四行(有效性范围)+ 证书头注逐字携带"只证编码后的约束集;proven 不消除 M4003";文档禁用"证明程序正确"表述 |
| 3 | 覆盖率随证明面扩面下降,被当成回归缺陷 | 中 | 第三行非承诺 + 实现时对"无证书的 proven"输出**具名**标注(如 `; 无证书:判定来源非实数不可行核`),不静默略过 |
| 4 | 证书格式成为事实标准后被我们改坏 | 中 | 判据冻结 + 弃用流程(stability-contract §4)+ fixtures |
| 5 | Alethe 旁路被误读为 Ming 能力 | 中 | §6.3 第五行非承诺 + §6.4 配方措辞;不提供 `--proof-format alethe` 取值(避免"有旗标 = 有承诺") |
| 6 | 第三方实现检查器时归一规则理解偏差(尤其 `<` → `<= c−1`) | 中 | 判据表述自包含(§3.4 表)+ 参考检查器 + 一组小语料作为"测试向量"(proven/loop/vacuity/常量矛盾/多重引用) |
| 7 | 真空 `proven` 被当成"边界已证"汇报 | **中**(空区间形态无需任何 `requires` 矛盾即可出现) | **独立 `vacuous` 字段**(对 `eff` 第二次求解;`uses_goal` 不能替代,§3.4);措辞纪律:`uses_goal=false` 可证真空、`true` 不可证非真空;文档说明 vacuity 的语义(不变式在该路径上不承担义务) |

## 10. 诚实边界声明(逐条"不得表述为")

1. **不得**把本 ADR 或其中的证书说成"Alethe 实现"——它是**另一种对象**(线性不可满足证书),不冒充 Alethe 语法。
2. **不得**把"z3 能消费我们的 VC 并回答 unsat"表述成"Ming 产出了证明"——z3 复核的是**结论**,证明的作者仍缺失(这正是 S-3 要补的位)。
3. **不得**把证书表述成"程序正确性证明"——它证的是"该义务编码后的约束集不可满足";编码忠实性与运行时安全都不在其内(§5.5;proof-protocol §7:证明只报告,不改运行时语义)。
4. **不得**把"证书覆盖**当前索引义务面**的 `proven` 全体(结构性预期)"表述成已实测事实——实现批次必须逐条确认后才可写入 GUIDE/协议;也不得把该预期扩到 §3.3 的三条无单一负环路径(`==` 目标 / 防御性中断 / 仅 `constFalse` 布尔)。
5. **不得**把 Alethe 生态的成熟度说成"可用/稳定"——它处于研究/实验阶段,`§2.2` 四项全部待核实。
6. **不得**把"未采集的义务"与"已证明"混用——proof-protocol §7 的口径逐字沿用:**义务未采集 ≠ 已证明**,证书只覆盖"已采集"的那部分。
7. **不得**在未跑 `node tests/run.mjs` 全量的情况下声称"S-3 交付完成"——本 ADR 本身零实现、零测试改动,只交提案。
