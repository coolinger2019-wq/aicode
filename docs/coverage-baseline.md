## 口径(先读再比)

- **行覆盖为 range 近似口径,非精确语句覆盖**:一行被覆盖 = 存在 `count>0` 的函数 range 覆盖该行。
  range 以函数体为单位,已执行函数体内未走到的分支行同样被计入(偏高);模块顶层代码不属于任何真实函数,不计入(偏低)。
- 行覆盖分母为**可覆盖行**:非空且非纯注释行(空行与纯注释行不计入)。
- **函数覆盖** = `ranges[0].count > 0` 的真实函数(V8 顶层包装条目排除)。
- 数据来源:`NODE_V8_COVERAGE` 插桩跑 `tests/run.mjs` 全量(主进程 + 全部子进程,同一脚本多进程取并集)。
- 只用于**同口径纵向趋势对比**,不与 istanbul/nyc/c8 等语句覆盖横向比较;信息性指标,不设门槛(plan §4.3.8:先建立基线再谈阈值)。

## 解读

- `diag.js` 行覆盖 36.9% 属口径现象:文件主体是顶层 `CODES` 常量表(不属任何函数,不计入),真实函数 9/11 已覆盖(v0.57 首测 37.2%,58/156,同现象)。
- `vm.js` 函数覆盖三测对比:43.8%(35/80)→ 63.8%(51/80)→ **65.9%(54/82)**;行覆盖 95.3% → 98.3%(846/861)。未覆盖的 28 个仍以 **wasm 宿主导入闭包**为主,不是 opcode;40 个 opcode 是 `execLoop` 内 case,函数覆盖率不度量操作码(plan 曾引用的 43.8% 旧口径已作废)。距 70% 还差 4 个具名函数(58/82)——信息性线索,不设版本门槛(plan §4.4.10)。
- `lsp.js` 随 v0.58 LSP 扩展函数面从 28 涨到 93,覆盖 81.7%(v0.57 首测 71.4%,20/28);`manifest.js` 3/4(75.0%,v0.57 首测 2/4)——分节用例面仍窄,信息性。
- `wasm.js` 行覆盖 89.7%(1309/1460)与 v0.57 首测(89.9%,1377/1532)基本持平;两测之间文件本身有增删,逐文件分母不可直接横比。
- `checker.js`(4582 可覆盖行)93.4% 对应 §4.3.8「checker 拆分」项的重构安全性参考线(v0.57 首测:4404 行 93.4%)。

## 并行会话注意

同时有其他代理改 `bin/ming.js` 时,插桩运行可能被打断(实测两次:`ming` 子进程瞬时产物缺失 → `tests/run.mjs` 在断言处抛未捕获异常,套件中止)。处理:重跑插桩套件至全绿再聚合;工具对解析失败/缺产物容错(跳过并计数),且信息性 exit 0(**非无条件**:临时目录 `mkdtemp` 创建失败会 exit 1,概率极低——plan §5.1 N-57.1 登记口径)。

## 复现

node tests/coverage.mjs          # 逐文件表 + 汇总(进度走 stderr;信息性 exit 0,mkdtemp 失败除外——见上)
