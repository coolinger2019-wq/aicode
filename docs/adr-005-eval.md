## 2. 四问逐一裁决

### 2.1 问 1:eval 代码来源与污点的交互——净化?禁止?

**裁决:eval 实参是污点 sink 位,登记后 M3049 自动覆盖;v1 不设任何授权 eval 的净化器——污点值无类型出口进入 eval。**

- **机制**:污点 v1(ADR-002)的 sink 门禁是"受保护槽位按 unify 拒绝"(M3049,checker 内 32 处发射点,判定载体无关)。eval 实参位登记为 sink(+1 槽位,约 1 行),`eval(Untrusted[str])` → 编译错误。
- **"先净化"为什么不可采纳**:净化器 = 可信根扩权,每个净化器登记"授权的 sink 位"(ADR-002 §3.4 纪律)。现有净化器的授权位是路径实参位 + CLI 匹配串——不含 eval。为 eval 新增净化器(如 `sanitize_code`)要求给"净化的代码"一个机械定义,而代码的语义是任意的:"校验不改写"的字符闸(拒控制字符)拦不住语义;任何字符级白名单都会让"审核通过 = 可执行任意代码"成为错觉。**定义不清的可信根比没有更危险**(ADR-004 §4.2 同款论证,原样适用)。
- **合法来源集**:字面量 + 程序内合成的净 str(模板拼接、插件文本经程序自身逻辑生成)。**"外部输入永不动态执行"由类型系统机械保证**——这是 Ming 的 eval 与其它语言 eval 的决定性差异:其它语言的 eval 是污点模型的死角(数据流分析绕不过字符串拼接),Ming 的 eval 是污点模型的一个普通 sink。
- **若未来出现真实用例**(如需执行用户提供的插件脚本):按族扩展纪律另裁决(专属净化器 + 独立威胁模型 + 授权位登记)——登记不预支,本 ADR 不为其留语法或接口占位。

### 2.2 问 2:效果声明与静态检查的边界——M 检查在哪层?编译失败怎么表达?

**裁决:eval 产物是完全独立的编译单元,全部 M 检查(词法 M1xxx / 语法 M2xxx / 类型·效果·契约·污点·穷尽性 M3xxx)在内层原档执行、零降级;外层唯一可见的是一个 builtin 签名 `eval(src: str) -> Result[str, str]`,效果 `eval`。编译失败与运行时失败一律 Err 化。**

- **内层(全检查)**:eval builtin 的实现 = REPL 同款管线(§1 已核实):`new Checker('<eval>', () => src)` → `run()` → 编译失败则 Err;通过则 `VMInterp` 执行其 `main`。内层 main 自行声明效果(`fn main() with io, fs { ... }`),M3029/M3030 在内层强制——**效果审计跟着字符串走**。外层不做任何对内层的静态分析(不知道、也不假装知道内层做什么)——这正是"独立编译单元"的含义。
- **外层(签名即全部)**:外层代码调用 eval 与调用任何带效果 builtin 无异;调用方必须声明 `with eval`(M3029 逐层传播,checker.js:1410 既有推导)。`eval` 效果的语义 = "本函数执行动态编译的代码,其内部效果不可枚举"——与 `proc`(exec 运行外部程序做任何事)同款的能力粒度声明,design §2.13"效果 = 这个函数会做什么的静态陈述"的直接延伸。**不是 mask 式的隐瞒**:字符串里写着什么,审计者 grep 字面量就能看到;动态拼接使字符串内容不可静态审计——这个固有代价由 `with eval` 这行签名如实标出(有动态执行这件事本身可见,内容不可见),与 ADR-003 的立场一致:可见性加在"事实存在"的层级。
- **编译失败 → Err(design §2.4"错误是值")**:Err 载荷 = `--json` 协议同构的 JSON 字符串(`{"ok":false,"diagnostics":[...]}`,bin/ming.js:189 `diagJson` 同源序列化)——调用方 `json.parse` 后按现有 --json 消费习惯处理,AI 修正回路直接复用。**运行时失败同通道**:内层 panic(M4003 越界/M4015 契约/M4006 unwrap...)与配额熔断(M4001 步数/M4012 墙钟/M4011 分配)在 eval 边界捕获 → 同形态单诊断 JSON 的 Err。**panic 不穿透 eval 边界**:内层程序的失败是外层的值,不是外层的崩溃——与 std.ffi.load 失败 = Err 先例(design §6.9)同构,也是 sync 子任务"panic → join Err"(capabilities 错误隔离行)的同款语义。
- **契约纯性自动拦截**:契约表达式在空效果集下检查(mask ADR §3.2 已核实的机制),契约内调 eval → M3029——零新机制,契约里不可能藏动态执行。
- **main 正常返回(含非零退出码)→ Ok(stdout 捕获)**:退出码语义属进程边界,不进 v1 的 Err 判定(评审清单 4)。

### 2.3 问 3:引擎限制——eval 恒走 tree/VM?wasm/cc 不做运行时编译?

**裁决:内层恒走 VM 字节码(REPL 同款),不提供引擎旗标;外层 `with eval` 函数永不进 wasm/C 资格;`ming build` 显式回退源码模式;cc 发射期拒绝。wasm/cc 运行时编译不做——这是范围裁决,不是能力边界,如实登记。**

- **外层资格(自动,零新机制)**:wasm 资格对效果的放行集只有 ffi/unsafe 旗标(src/wasm.js:451–456,`![...sig.effects].every(effectOk)` → 不可 eligible),`eval` 不在其中 → `with eval` 函数不 eligible;主程序回落 VM(default 引擎本就是 VM,行为无差异;strict 模式如实报告)。cc 路径同款:C1/C2/C3 旗标放行集不含 eval → 发射期显式拒绝(C1 形态)。`ming build`:沿 unsafe 先例(design §6.10"不安全代码永不进 AOT 快路径")——遇 `with eval` 显式回退源码模式并说明原因。eval 程序的部署形态 = 源码 + Node,诚实声明。
- **内层不做 wasm 的理由**:① eval 的用例是动态性(REPL/脚本/模板),不是性能——性能路径是文件级 AOT;② wasm 编译/实例化 per-call 开销 + 缓存复杂度(内容寻址缓存是 build 期机制,运行时无缓存面);③ cc 运行时编译需要 gcc 在场 + 动态加载,交付面爆炸(无编译器环境/交叉编译场景直接不可用)。**诚实评估**:技术上可行(vm.js 宿主本就在进程内,wasm 编译器可调用)——"不做"是成本/复杂度裁决;若未来出现"热循环动态生成纯函数"的真实用例,内层 eligible 面(无 io 的纯函数)可评估二次入口——登记远期,不预支。
- **内层恒 VM 的另一含义**:eval 产物吃不到 wasm/cc 加速——内层性能 = VM 性能。动态性换性能,明示取舍。

### 2.4 问 4:eval 与热重载的范围切分

**裁决:v1 只做 eval;热重载不做、不预留语法面、不写占位——真实需求出现时另 ADR。**

- **语义面完全不同**:eval = 单次字符串编译执行——无状态、无常驻、无模块图、无增量;调用结束即丢弃。热重载 = 常驻进程内模块替换——需要 ① 触发机制(文件监听/信号);② 模块缓存失效(进程内 build-cache 语义);③ **在途状态语义**(serve 在途请求对旧/新 handler 的归属);④ 回滚与失败语义(新模块编译失败时服务怎么办)。每一项都是独立裁决面,与 eval 共享的只有"运行时编译"这一个底层动作。
- **需求侧无证据**:热重载的唯一现实宿主是常驻 serve,而 serve 连远小于热重载的增量(优雅停机,实现路径已预留、约 30–50 行)都在 12.8 分钟真实服务观察后 **no-go 推迟**(plan §4.5.3 任务 3 / §4.6.5)——常驻面需求尚未实证,为它预设计撤/语法是猜测性投入(v0.66 立场"不做反馈真空期的猜测性投入"原样适用)。
- **eval 落地即热重载的最小验证路径**:若真实需求出现,先用 eval 组合("循环里 eval 新版本模块")验证需求形态,再裁决热重载 ADR——需求先于设计,设计先于实现。

## 5. 安全面诚实清单(eval 落地后仍然成立的威胁面,如实登记)

1. **eval = 任意代码执行,同进程执行**。`with eval` 是签名级事实,不是安全边界:内层代码与外层共享同一 Node 进程,无 worker 隔离(对照 serve 的每请求隔离子 VM,interp.js:2473)。eval 不承诺沙箱——它承诺的是**可见性**(谁在动态执行,签名里一行字)与**来源纪律**(污点无出口),不承诺"动态代码无害"。
2. **serve handler 白名单不含 eval**(checker.js:260/:4131–4138,M3002 白名单拒绝)——常驻网络面(handler 效果白名单 8)默认拒绝动态执行。若评审认为需要放开,属独立威胁评估(serve 的请求载荷 + eval = 网络输入驱动编译,本 ADR 明确不开这个口),按 ADR-001 清单模式另裁。
3. **污点联动是类型级保证而非内容审查**:M3049 拦的是"污点标签值"进 eval;程序内合成的净 str 内容仍可任意(程序自己拼出的代码 eval 自己执行,类型系统不评价其内容)——污点承诺边界 = "未经净化(此处:无净化器,即污点值)不进 sink",沿 ADR-002/004 同款口径。
4. **panic/熔断 Err 化是隔离也是语义裁决**:内层 M4003/M4015/M4001/M4012/M4011 不穿透边界——外层程序不会被内层杀死(隔离收益);代价是内层违约从"进程级 panic(栈+源摘录)"降为"Err 里的一条 JSON 诊断"(诊断退化,见 §6 ②)。
5. **配额按调用重置(沿 sync 先例)**:内层 interp 以全量 maxSteps/maxMs/maxAlloc 启动(interp.js:562 同款),且外层在 eval builtin 阻塞期间不轮询自身配额——`--max-ms 100` + 循环内 eval = 每次调用各自 100ms,**总预算按调用次数放大**。v1 沿先例全量继承并如实登记此窗口(GUIDE);"共享墙钟基线/剩余预算传递"列实现期裁决项,不预支。
6. **确定性承诺的表述**:eval 不引入时间/随机/哈希序行为——同一 eval 字符串产生同一编译产物与同一行为;**"程序做什么"依赖运行时字符串**这一事实由 `with eval` 签名如实表达。eval 字符串来自环境输入的场景已由污点面拦截(§2.1),来自程序自身的场景确定性不变。

---

## 6. 局限诚实清单

1. **per-call 编译开销,无缓存**:每次 eval 走全管线(词法→解析→全检查→字节码编译)。REPL 每 输入同款,单次毫秒级;高频调用(循环内 eval)不适用——v1 无产物缓存(内容寻址缓存是 build 期机制),缓存列远期候选不预支。
2. **诊断质量低于文件级**:内层诊断 file='<eval>',span 指向字符串内坐标;行号对齐可用(字符串内换行保留),源码摘录需把 eval 源喂入 cacheSourceLines(diag.js:172,REPL 同款);fix 处方位置可机器应用但"文件"不是磁盘文件。编译失败诊断的 --json 形态完整(码/hint/fix 不降级),但 LSP/编辑器跳转不适用。
3. **无值交换**:Ok 载荷只有捕获的 stdout——内层与外层不共享值域(struct/Vec/Map 不可传递);复杂数据交换经 json.stringify/parse(边界明确,拷贝两次)。引入动态值类型(Ming 版 any)违反"无隐式 anything"(design §1),不做——这是 Ok 载荷定为 str 的根本原因,不是实现偷懒。
4. **main 无实参**:eval 的程序面是"无参 main";参数化动态执行(传 args/传值)涉及 wire 序列化复用(spawn 先例)——列评审候选,不预支。
5. **eval 产物永不享受 wasm/cc 加速**;`with eval` 程序的部署形态 = 源码 + Node(build 回退源码模式)。性能敏感路径走文件级 AOT,eval 面向动态性。
6. **fuzz 合同不含 eval**:差分模糊器不生成 `with eval` 程序——eval 语义靠专项回归锁定,不享受四引擎差分合同的自动覆盖(与资格面具名回落同款诚实口径)。

## 8. 结论

**做——按"显式能力 `with eval` + 独立编译单元全检查 + Err 化(--json 同构载荷) + 恒 VM 内层 + 污点 sink 无净化器出口 + 热重载另裁"推进;实现走 go/no-go 条件承诺:§7 清单 12 项逐项裁决(架构师默认立场先行落盘,维护者事后复核)后进入实现,任一不勾,本 ADR 保持设计文档状态(plan 记录未满足项与理由,沿 ADR-001 §5.1 口径)。**

否决归档,不再复议(复议需新 ADR):污点值经"代码净化器"进入 eval(v1 无机械定义);eval 的动态值返回形态(违反"无隐式 anything");serve handler 内 eval(v1);热重载与 eval 同 ADR(语义面不同)。

**一句话**:Ming 的 eval 与其它语言的 eval 方向相反——其它语言把 eval 当逃逸舱口(跳出静态检查),Ming 把 eval 做成第 12 个门禁面(效果签名 M3029 可见、污点 sink M3049 拦截、serve 白名单拒绝、AOT 拒载、配额继承、panic Err 化):动态执行的全部事实都写在签名与类型里,唯一放进来的是"程序自己写给自己执行的代码"。
