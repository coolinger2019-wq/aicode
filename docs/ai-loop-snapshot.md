## 0. 口径(先于数字)

1. **语料**:24 个程序(e01–e24)。e01–e20、e22–e24 共 23 个为错误形态程序(对照第四轮 #60–#62 与 plan §4.5.3 任务 7 列举的形态),e21 为 serve 合规对照(预期干净,不进捕获分母)。每个错误程序在构造时人工指定"真实根因数"(独立错误数;e14 = 4,其余各 1),合计 24 个根因。
2. **捕获**:check 报告 ≥1 条 error 诊断(或 warning-only 亦可观察,单独注明)视为"捕获"。
3. **级联放大比**:报告诊断数(含 warning)÷ 真实根因数。逐形态给出;汇总口径 = **捕获语料合计**(21 程序;未捕获的 e05/e24 两项不进入报告诊断数,计入则分母失真——审查 MINOR-1 口径修正)。
4. **fix 结构化处方覆盖率**:诊断 JSON 带 `fix` 字段的码族清单;对照源码事实(`src/parser.js` 2 处 + `src/checker.js` 2 处赋值点)。
5. **误导判定**:hint 或 fix 会把修正引向非根因方向。三个可复核判据:应用 fix 后新增错误(f 探针实测)/应用 fix 后静默改变语义/应用 fix 后指向无关名。误导"命中数"按上述判据逐条计数,不凭感觉。
6. **处方应用后果探针**(f01–f05):把语料诊断给出的 fix 处方手工应用后另存为独立文件再 check——"自信但错误"必须用应用后的程序证明,不是看消息猜的。
7. **诚实边界**:语料是构造形态(非真实会话抽样);单机 Windows / Git Bash / Node v24.11.0;每形态每命令单次运行(诊断输出确定性,无计时敏感项);会话内的 rollout 不可消费(见 usage-audit.md §v0.66 节),本快照不宣称"真实 AI 修复率"。

## 3. 误导清单(逐条,均有应用后果实测或同机制对照)

1. **M3001 处方 `r`→`str`**(e13/e19):根因是 foobar 未声明;处方把失绑的 `r` 换成内置 `str`。应用后(f01)新增错误 `"str" 是内置函数,不能作为值传递`,根因原样保留——**#62 的"自信但错误"实测复现**。机制:毒化 let 失绑 + `nearest("r")` 在内置名里命中 `str`。
2. **M3001 处方 `e`→`Ok`**(e16):handler 效果违规毒化 match 值域 → `Err(e)` 臂失绑;处方把 `e` 换成变体构造器 `Ok`。应用后(f02)新增 M3005(`Ok 需要一个值`)+ M3012 保留。
3. **M3001 处方 `z`→`x`**(e14):`z` 因 nosuchfn 毒化失绑,nearest 命中同函数的 `x`(str)。应用后(f04)把级联 M3002("实际 ?")变成**真实新错误**("期望 i64,实际 str")。
4. **M3001 处方 `n`→`u`**(e04):应用后(f05)`debug(u)` 触发 **M3050 洗白禁面**——处方把用户引向污点禁面。
5. **M3001 处方 `n`→`s`**(e06):应用后(f03)可编译但**静默改变语义**(打印 s 而非长度;真实修复是 `.lenth`→`.char_len`)。
6. **M3012 hint"其他类型用 debug(x)"**(e19/e16):根因是拼错名导致值未绑定(实际是 ?)时,该 hint 指向不存在的修复路径(debug(未绑定名) 仍 M3001)——**#62 三形态复核成立**;注意 #62 登记时记为 M3002,现行发射码是 **M3012**(hint 文本同),登记与现行码存在漂移,如实记录。
7. **短名 nearest 命中内置 `Ok`**(e22 y→Ok、e23 x→Ok):单字母失绑名的编辑距离最近者常是内置 `Ok`/`Err`——处方系统性低质(同机制,未逐一应用,机制与 2/3 同源)。

附带发现(非误导但影响修正回路):

- **诊断排序**(e13/e19):M3003"无法推断 r"排在真实根因 M3001 之前——AI 倾向先修首条(标注 r 类型),徒劳一轮。
- **越界写静态静默**(e05):mut Vec 参数整函数放弃属文档化口径,但对 AI 而言"check 通过 + 运行时 panic"的落差只在运行期暴露。
- **无 requires 越界读全静默**(e24):边界证明以 requires 存在为前提("无 requires → 无边界可依");最常见的"裸下标"形态连 `--warn-unproven-index` 都不触发 W3105。运行时 M4003 消息带可行动后缀("用 .get(i) 返回 Option"),兜底质量好。
- **M3015/M3006 无 hint 字段**:信息在 message 内(方法全表/字段缺失),结构化 hint 缺位——"最接近方法"建议(M3001 已有 nearest 机制)与方法/字段族未对齐。
- **Json 点字段访问**(e15):M3006 不指向 `get("k")`,对 AI 是高频缺口(serve handler 载荷处理即此形态)。

## 4. v0.67"诊断协议校准" go/no-go

判据(**本批次采用,阈值已写入 plan §4.5.3 任务 7**——审查 MINOR-2 修正归属):go = 误导 hint ≥3 或 级联比 ≥2 或 fix 错误 ≥1;否则 no-go 转其它主题。

| 判据 | 门槛 | 实测 | 达标 |
|------|------|------|------|
| 误导 hint/fix 命中 | ≥3 | **7** | ✓ |
| 级联放大比(合计) | ≥2 | 1.75 | ✗(单形态最大 4×,#62 族全部 ≥3×) |
| fix 错误(应用后更糟) | ≥1 | **4**(f01/f02/f04/f05 实测 + f03 静默改语义) | ✓ |

**结论:GO**——三项判据两项达标(误导与 fix 错误均远超门槛),且全部有可复现的应用后果探针支撑。级联合计口径未达 2,但 #62 修复应聚焦的形态族(失绑毒化 + nearest 内置名命中 + 毒化排序)恰是 3–4× 集中区。建议 v0.67 校准的三个最小切口(按实测收益排序):(1) 毒化 let 失绑时不发 M3001-nearest 处方(或对"根因已报 M3001 的名字"抑制第二处方);(2) nearest 候选排除内置 Ok/Err/str 等构造器/内建函数值;(3) M3003 在同表达式已有 M3001 时不先发(排序修正)。M3048/M3045/M3029 等既有码质量好,不在校准面。
