## 1. 背景与登记窗口

v0.77(ADR-007 清单 3)引入第三载体 `Untrusted[Vec[u8]]`(`fs.read_bytes`/`read_bytes_range` 同源同污),操作面 = `UNTRUSTED_METHODS.vec = ['len', 'is_empty']`(checker.js:735)——**字节是黑盒**:长度可查、值不可读。三道闸把消费面全部关死:

1. **元素读 → M3020**:下标路径按基类型分派,`Untrusted[Vec[u8]]` 非 vec 形态落通用分支 `不支持下标索引`(checker.js:2745 区);`.get(i)` 不在 vec 白名单 → M3050。
2. **字节→数值消费 → M3049**:`bin.unpack_u16_le/be`…`u64`(checker.js:559–563)参数槽为净 `Vec[u8]`;`to_str` 污字节载体无此方法(GUIDE §18:"仅净 Vec[u8] 有——元素消费面维持净槽");crypto/re 面净槽同判。
3. **跨污界 `==` → M3002**:`==` 走 unify 精确匹配——污污合法、污净拒绝(GAP-S3-3 实测);`std.unstr.mark` 仅 str 载体(checker.js:638),i64 常量侧无法标污,比较通道无绕行。

## 2. 目标与非目标

**目标**(全部为 additive,无签名翻转):

1. **G8 关闭**:`Untrusted[Vec[u8]]` 从黑盒变为可按值消费——元素读/字段提取/校验和判定全在污域完成,hex 传输编码桥退役;
2. **R-5 兑现路径打通**:S3 场景升级纯二进制捕获的实现前置就绪(实现批次衔接,R-5 场景改造本身不在本 ADR 范围);
3. **污标量代数最小完备**:污标量可声明、可运算、可比较、可过 sink 门禁——类型面自洽,无惰性死角;
4. **零洗白出口漂移**:保污面与净出口逐一过审(§4.6),净化器族不扩,既有禁面(M3049/M3050/print-debug/插值/as)逐字不动;
5. **引擎与诊断零新机制**:wasm/C/运行时走既有载体机制,零新增 M 码。

**非目标**:见 §8(明确不做)与 §9(诚实边界登记不预支项)。

## 4. 问题全景(crux 枚举——把问题考虑全面)

### 4.1 元素读:污数组下标读返回什么(核心决策一)

**为何保污而非净**:提取出的字节是未经验证的攻击者可控原始数据——"校验 ≠ 净化"(ADR-004 §3.4:"handler 校验过的字段仍是污,唯一出口是净化函数")纪律下,读取本身不得构成洗白出口。净侧先例(Json.as_num → 净 f64,ADR-004 清单 9)的对象是**已被 json.parse 门解析过的结构化值**;原始字节无任何语法门在前,不可类比。`parse_i64` 的 Ok 净值同理——解析即校验门,Ok 承载的是"通过门的值";原始读取在门之前,污标量是门前的原材料。

**为何 i64 而非 u8**:`Untrusted[u8]` 是 checker 待解锁清单具名项(checker.js:1035——"u8 原始载体/其他容器等,按净化器授权矩阵另裁决"):为元素读开启第五原始载体,收益为零(值域 0–255 本就要拓宽参与算术),成本是整套载体机制(白名单/unify/doc/LSP/资格面)。**i64 拓宽一次到位**,窄型算术门禁(v0.85 fits 门)对污路径不适用(污域统一 i64,无回绕面)。

**净污不对称如实登记**:净 `Vec[u8]` 元素读返回 u8(窄型,既有),污返回 `Untrusted[i64]`——刻意不对称,GUIDE 登记口径(清单 14)。M4003 越界 panic 消息与退出码 101 与净 Vec 同轨逐字(确定性契约,AGENTS §6.1)。解锁双形态:`v[i]`(panicking,与净 Vec 同语义)与 `.get(i)`(Option 形态,对齐 Json.get/at 投影表形态)。

### 4.2 污标量代数(THE CRUX):没有算术传播,解锁没有意义

元素读产出 `Untrusted[i64]`——若污标量是惰性值(无算术/无比较),解析器一行都写不出来:`length` 字段要 `len & 0xFF` 掩码拼接、`end = header + len` 偏移推进、`len <= frame.len()` 边界判定、Fletcher-16 要 `sum += b`(S3 现有 Fletcher-16 为 mod 255 累加,I6)。**污标量必须可运算**,裁决沿 v0.77 微调①先例(拼接传播:污+净→污,拒截面后移到消费 sink——"禁它的前提是当时无传播;有传播后禁令理由消失"):

| 运算类 | 算符 | 任一操作数为污标量时 | 污点语义 |
| 宽度门禁 | 算符 | 污标量(i64 主宽) × 净窄型(u8/i16/i32) | **不放宽**:宽度门禁 M3013 照旧适用于污标量组合,污路径不隐式拓宽净窄型操作数(无隐式转换原则);污标量仅与 i64 域自由组合(S3 场景的净常数表/净偏移用 i64 字面量即天然匹配) |
|--------|------|----------------------|----------|
| 四则 | `+ - * /` | 结果 `Untrusted[i64]` | 保污传播(拼接传播同构;i64 域封闭) |
| 取模/移位/位运算 | `% << >> & \| ^` | 结果 `Untrusted[i64]` | 同上——位掩码是协议解析主食(b & 0x0F) |
| 相等 | `== !=` | **净 bool** | 污点在布尔上终结(ADR-004 清单 9 eq 原文:"实参载体放宽为净或污均可——比较不外流载荷") |
| 关系 | `< <= > >=` | **净 bool** | 同上——长度边界判定的基本原语 |
| 一元取负/`!` | `-` `!` | 污标量 `-` → `Untrusted[i64]`;`!` 仅 bool 不涉 | 传播对称 |

- **必要性硬约束(比较放宽)**:常量侧无法标污(`std.unstr.mark` 仅 str,checker.js:638;污污 `==` 虽因 unify 精确匹配合法,但 magic byte 比较必然是污 vs 净常量)——不放宽则"从帧里读出一个字节并和期望值比较"不可写,G8 关闭是空话。
- **范围限定**:比较放宽**只限标量(i64)**;str/Json/Vec[u8]/Map 载体的跨污界 `==` 维持 M3002 现状不动(GAP-S3-3 口径不变);污污 `==`(既有合法)维持不动。
- **除零/移位越界**:panic 语义(M4002,消息与退出码逐字)与净值同轨——污值不改变运行时行为(擦除),四引擎差分照常锁定。
- **复合赋值**:`污目标 += 污值/净值` 合法(污点只增不减);净目标 += 污值 → M3049(v0.77 微调②机制载体无关自动覆盖,实现期核验)。
- **f64 污标量不引入**:无来源(元素读只产 i64),登记不预支(§9)。

### 4.3 字节→数值消费:复用 unpack,不造方法族(核心决策二)

候选"to_u16/u32/i64(端序显式参数)类方法"**否决**:`bin.unpack_u16_le/be`…`u64` 已存在(净槽,checker.js:559–563,端序在函数名中显式),另造方法族 = API 不对称 + 双份漂移(ADR-007 清单 6 对 write_raw 变体的否决理由:"另造变体否决:API 不对称 + 诱导双份漂移"——逐字适用)。裁决:**unpack 族参数槽改载体感知参数位**(先例 = `index_of` 的 hay 位,GUIDE §18:"载体感知参数位——污 str 合法流入纯函数计算,输出污点终结于标量";本处输出不同:提取语义载荷保污):污字节流入 → `Result[Untrusted[i64], str]`(载荷保污,提取语义同 §4.1);净路径逐字不变(签名面不动,只加感知)。溢出语义净污同轨(u64 > i64::MAX 的既有行为,实现期核验锁定)。

**Err 载荷审计义务(ADR-007 审查 B1 先例——"Err 文本回显污内容且为净 str"曾是 BLOCKER)**:实测 unpack Err 文本为位置信息(`unpack:偏移越界(需 [off, off+size),长度 N)`,interp.js:2926)不含字节内容回显——Err 保持净 str 合法;实现期对全部 Err 路径复核一次,若发现内容回显位则 Err 载荷翻转保污(B1 同款处置,不许静默)。

### 4.4 字节→hex:to_hex 保污(核心决策三)

新增 `Vec[u8].to_hex()`(纯函数,无效果):净接收者 → 净 str;污接收者 → **`Untrusted[str]`(keep)**。必要性:协议工具的十六进制展示/中继/日志是二进制处理的标配出口(hex 编码需求从 G8 场景倒推——S3 的帧格式本身即以 hex 落盘)。**保污必要性论证**:hex 是内容保持的双射编码(可完全逆变回原字节),输出净值 = 字节级洗白通道(污字节 → hex → 净 str → 任意 sink)——保污使全部 sink 门禁继续生效,回显走既有出向透传位(print 家族,v0.77 §8.1 微调先例:stdout/stderr 是存储面,污值写出 = 存储非边界穿越)。与 str 代数 keepBytes 位(bytes/to_bytes:"内容字节化,污点跟随字节,与 read_bytes 第三载体对称")互为镜像:to_hex 是"字节文本化,污点跟随文本"。对称面 `from_hex` 不预支(§9):S3 升级纯二进制捕获后,污侧 hex 解码需求消失,净侧 from_hex 另登记候选。

### 4.5 与 G9 合流:校验和族的槽语义预裁决(核心决策四)

G9(crc32/adler32 无内建,Fletcher-16 替代)落地门槛独立(R-7:"T3 场景之外 ≥2 个真实校验需求",plan §4.20 P2)——本 ADR **只预裁决槽语义,不预支内建添加时机**:

| 合流形态 | 输入槽 | 输出 | 裁决 |
|----------|--------|------|------|
| a) 净槽(现状同构) | 污 Vec[u8] → M3049,需先"净化" | 净 i64 | **否决**——循环论证:校验和存在的理由就是数据不可信,要求"先净化再校验"等于要求在验证前给出验证结果;且二进制无机械净化器,唯一绕行是 hex 桥 = G8 不关闭 |
| b) 载体感知参数位 | 污/净 Vec[u8] 均可流入 | **净 i64** | **采纳(预裁决)**——固定宽度摘要,内容不复存,不构成字节级洗白 |

**统一裁决线(贯穿本 ADR 的判据)**:"解释性聚合与语法门输出净、原始提取输出污"——`parse_i64` Ok 净(解析即门)/Json.as_num 净(结构已解析)/crc32 净(聚合摘要)同判;unpack/元素读污(原始提取,无门在前)。校验和输出净的洗白审查:摘要值可被攻击者影响(碰撞),但污点承诺边界 = "未经净化不进 sink",摘要不是内容——碰撞对抗是协议设计问题不是污点问题(§9 如实登记)。

**污标量算术的兜底价值**:若 G9 未落地,污标量算术传播(§4.2)使 Fletcher-16 可在污域手写(mod 255 累加全保污,与期望值比较净 bool)——**R-6 不依赖 R-7,依赖方向正确**:R-7 门槛若永不满足,污域手写校验和仍是合法路径。

**奇偶性登记**:crypto str 面(sha256/hmac_sha256 净槽,M3049)维持不动——"污 str → crypto"的合流是另一轮裁决(登记不预支,§9);本 ADR 的摘要裁决只覆盖**字节位**的未来族(crc32/adler32/fletcher 等),不追溯既有 str 面。

### 4.6 洗白旁路审查(全表过审——清单 9 义务)

| 新面 | 输出 | 审查结论 |
|------|------|----------|
| 元素读 `v[i]`/`.get(i)` | `Untrusted[i64]`/`Option[Untrusted[i64]]` | 保污,无出口 |
| 算术/位运算传播 | `Untrusted[i64]` | 保污,无出口 |
| 比较运算 | 净 bool | 布尔不携带内容(谓词/Json.eq 既有判据) |
| unpack 族(污路径) | `Result[Untrusted[i64], str]` | 载荷保污;Err 净 str 以 B1 审计义务为条件(§4.3) |
| to_hex(污接收者) | `Untrusted[str]` | 保污(hex 可逆变,净 = 字节洗白通道) |
| 校验和族(未来,污路径) | 净 i64 | 摘要内容不复存;唯一净出口之一,审查通过(§4.5) |
| **污标量的方法/trait 面** | 无新增面 | **空白名单**——`UNTRUSTED_METHODS` 无 int 载体键 → 污接收者任何方法调用(含 `to_str`/Debug trait 分派)一律 M3050(既有中央闸门 checker.js:5135–5150 自动覆盖);**防堵形态** = 污 i64 → `to_str` → 净 str → exec/path/eval sink 净串注入。义务核验 6 的覆盖范围含此面 |

**净化器族第四次不扩**(ADR-004 §4.4 四条理由逐字适用):二进制内容无机械净化定义——"干净的字节"因协议而异(什么算合法帧是领域逻辑不是净化器);校验/边界判定由污标量代数在污域完成,不需要 sanitize_bytes。`assume_clean` 逃逸舱继续不做(ADR-007 清单 12:"显式信任断言破坏'来源必污'构造性保证")。**Untrusted[i64] 白名单位无直接来源**:来源纪律不新增 source——污标量仅由提取/算术衍生,extern 返回污标量登记不预支(§9)。

### 4.7 引擎面:v0.61 机制自动覆盖,零新机制

wasm 资格(compiler tryWasm 顶层形参载体解包,v0.77 已覆盖 `Untrusted[Vec[u8]]`;污标量形参 `Untrusted[i64]` 解包后同 i64 口径——v0.61 先例)/C 后端(mingTyNum 载体穿透,cbackend 既有)/运行时(擦除——checker 类型计算不影响 interp/vm 行为,元素读/算术/unpack 的求值路径与净侧同一实现)/cc(C1–C6 旗标放行口径不变)——全部走已验证机制,实现期回归核验。**具名核验项**:① unpack/to_hex 作为内建在 wasm 编译函数内的资格沿 str.join 先例(REJECT → strict 具名回落 exit 2,不影响语义正确性,AGENTS §9 口径);② 净 `Vec[u8]` 元素读 wasm 资格 v0.63 已交付(宿主 panic_m4003 导入),污路径同代码路径,`MING_WASM_DEBUG=1` 核验无 REJECT。

### 4.8 版本与变更政策

实现窗口 = **v1.1 候选**(plan §4.20.3 映射:R-6 + R-5 同版;顺序 = 先 R-6 实现、后 R-5 场景升级)。本批是 **additive 解锁**而非签名翻转:全部新行为此前都是编译错误(M3020/M3050/M3002/M3049),不存在依赖拒绝行为的合法程序——**既有合法程序零影响、零校准**;需校准的只有"负例断言变正例"的既有测试位(逐条理由化,沿 ADR-007 §2.10 口径——语义翻转面零校准不适用,但仅限负例位,工具迁移面为零)。M3020 已发布码不改号不删除(AGENTS §6.2 纪律):该类型停止触发,其他类型(str/元组/Map 等)的消息与 hint 逐字不变;冻结令面(类型面/效果名/诊断码族)无新增——污标量载体是既有 Untrusted 构造器的白名单 +1,不是新冻结面条目(此判断随复核位一并确认);清单 7 的 `to_hex` 为**新增方法面**(AGENTS §6.8 冻结令具名面含"内置函数"),实现窗口 v1.1 在解冻后、冻结令不再约束,冻结期判断仅涉载体白名单(复核位一并确认)。

## 9. 诚实边界(落地后仍存在/登记不预支的窗口,如实登记)

1. **净污不对称是特性不是疏漏**:净 `Vec[u8]` 元素读 → u8、污 → `Untrusted[i64]`——两套类型面并存,GUIDE 明示;依赖窄型语义的净侧代码迁移到污域时宽度语义变化(u8 回绕门 → i64 无回绕)需作者知悉。
2. **unpack Err 净 str 是有条件裁决**:以"Err 文本不含内容回显"的 B1 审计为前提(§4.3);实现期复核若推翻前提,Err 载荷翻转保污。
3. **摘要碰撞不在污点承诺范围**:校验和输出净 i64 可被攻击者构造碰撞(crc32 尤其)——污点承诺边界 = "未经净化不进 sink",不是"内容不可伪造";碰撞对抗是协议设计问题(密码学摘要另论)。
4. **比较放宽泄漏一位信息**:污标量比较输出 bool 泄漏比较结果——与谓词(starts_with/contains)/Json.eq 同判(既有口径),不是新窗口。
5. **污标量是载体白名单 +1(i64)**:类型面扩大(第五载体位),虽无直接 source、无字面量构造,但 extern/契约/证明面与其交互实现期核验;静态边界证明面与污标注正交——污下标读的义务采集不预支。
6. **ADR 落盘 ≠ G8 关闭**:实现批次未启动前现状不变(M3020/M3049/M3002 照发),S3 场景 hex 桥继续有效;本 ADR 只裁决不改现状(ADR-004 §5 ⑤ 同款)。
7. **负例断言校准**:既有"污 Vec[u8] 元素读拒绝"类负例位将随实现翻转,逐条理由化登记——不是静默放宽。

## 11. 裁决建议汇总(架构师延伸,待维护者复核——非已裁决记录)

§5 清单 14 项默认立场即本 ADR 的裁决建议,四条主线:**① 元素读解锁保污、不引入 u8 载体(清单 1/2/3);② 污标量代数 = 算术传播 + 比较放宽(清单 4/5,本 ADR 成立的先决条件,与 ADR-007 清单 4"污值代数是真正核心"同构);③ 统一裁决线"解释性聚合净、原始提取污"贯穿 unpack/to_hex/校验和(清单 6/7/8);④ 洗白审查通过、净化器族第四次不扩、引擎零新机制、零新增 M 码(清单 9/10/11)**。清单 12/13/14 为验收三件套(fuzz 字节形态/场景纯二进制化/文档三处登记),随实现批次执行。任一项复核否决 → 本 ADR 修订对应条目后重排;全部通过 → 按 §10 另排实现流水线。

**一句话**:G8 的本质不是"给字节开一个读口",而是"把污值代数从 str 载体推广到标量域"——元素读/算术/比较三条裁决让攻击者字节在污域内可解析可验证,而唯一两处净出口(摘要与布尔)内容不复存;hex 传输编码这一 workaround 自此退役,纯二进制协议解析成为污点系统的正面能力而非绕行产物。
