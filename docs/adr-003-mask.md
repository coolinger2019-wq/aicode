# ADR-003:mask 效果屏蔽——裁决:不做,永久移出 Backlog

> **状态**:评审中(2026-11-13,plan §4.3.7 任务 2 交付)· **日期**:2026-11-13 · **版本基线**:v0.58.0(825 项回归全绿)
> **立场声明**:本 ADR 只交付设计裁决,**不写任何语言实现代码**。文中"实测"均附复现命令(环境 Node v24 / win32-x64 / 2026-11-13);"源码确认"标注文件:行号;无一处来自想象。
> **结论先行**:**不做**——`mask [效果]` 从 Backlog 永久删除,design §6.11 标注为"已否决(本 ADR)"的历史记录。理由不是"还没准备好",而是与第一原则的结构性冲突:**mask 的功能定义就是"让签名看不见真实效果"**,它破坏的是"程序的含义必须和它写出来的一模一样"(design §1)与"每个危险操作都是签名里的一行字"(design §6.7)。v0.46 起 M3029 的结构性推导、契约纯性、四后端资格三个单一事实来源全部以 `sig.effects` 为输入,mask 要求每个事实来源都"感知一处签名里的谎言"——维护面持续膨胀,且每一处防线都是补丁而非设计。
> **关联**:docs/adr-001-concurrency.md(同系列)、docs/adr-002-taint.md(污点:数据级方案,与 mask 无关)、docs/design.md §6.11(v0.44 mask 设计定稿)、§6.10(unsafe 双门禁)、§2.13(效果系统)、§2.16(三期门禁)、docs/plan.md §4.2.2/§4.2.8(ADR 表与 Backlog 降级记录)、§4.3.7(任务书)、docs/moltbook.md(diviner 信任边界议题)。

## 1. 复核对象:v0.44 设计定稿(design §6.11)

v0.44 的定稿内容:动机("安全门面 API 无法构建"——底层用锁/文件/ffi 的内部实现,对外应当是纯签名)、语法(`mask [fs] { ... }` 块,块内可调用 fs 操作,所在函数签名**可以不**声明 fs)、四条健全性条件、与 `with unsafe` 的关系("mask 是不安全代码的安全门面出口,两者共用逃逸分析")、拒绝的替代方案(自动推断/函数级属性)。

四条健全性条件在今天的复核:

| 条件(v0.44) | 今天的事实 | 复核结论 |
|---------------|-----------|----------|
| 1. 效果承载值不得逃逸块(资源句柄不可出现在返回值) | Ming **无 File/Lib 类需 close 的资源句柄**:ffi 是 extern 直调(无 Lib/Fn 句柄——`lib.fn` 运行时 API 已从 Backlog 删除,plan §4.2.8),fs 返回 `Result`(无 File 句柄),"谁加载谁释放、无 GC 句柄注册表"(design §6.9/§6.10);唯一句柄 `Join[T]` 已被线性纪律(M3034:句柄不得存入集合/struct 字段/元组/enum 载荷,只活在单个绑定,GUIDE 并发节)+ scoped 块(v0.17,块结束必汇合)显式解决 | **前提不存在**:要防的"句柄逃逸"在 Ming 的 API 设计里没有宿主。mask 的原始动机(包装资源句柄)落空 |
| 2. 块内 panic 语义不变 | 成立(panic 不是效果) | 成立但与争议无关——争议不在 panic |
| 3. mask 只影响声明表面,不影响求值语义(加不加 mask 运行时一致) | 这正是问题所在:它把"声明表面"定义为可撒谎的层 | **该条件本身即冲突**:签名与真实效果的分离被制度化为特性 |
| 4. 未做静态证明前,mask 是开发者担责的显式声明,与 `with unsafe` 同级 | unsafe 的"担责"是:在双门禁(签名 + 块)围出的显式区域里做**类型系统无法验证的事**;mask 的"担责"是:把**类型系统已经机械验证的事**(M3029 效果传播)重新关闭 | **方向相反**:unsafe 是明示例外,mask 是隐身通道。同级声明不成立 |

## 2. 与第一原则的冲突(为什么"签名看不见的效果"不可接受)

1. **design §1:"程序的含义必须和它写出来的一模一样"**。`fn f() { mask [fs] { ... } }` 写出来是纯签名,含义是读盘——名字就叫"明"的语言不能内置这个语义。
2. **design §6.7:"每个危险操作都是签名里的一行字"**(差异化主张)。mask 把这行字擦掉,换取"门面"便利——但 Ming 的立场是"宁可有传播税,也不要默认纯但随时可能偷偷 IO 的世界"(design §2.13)。**传播税是特性,不是缺陷**。
3. **design §2.16 三期门禁:"无法把带效果函数重新分类为普通代码——签名差异机械可见,治理只能通过签名变更(可 review)完成,不存在绕过"**。mask 恰好是"把带效果函数重新分类为普通代码"的语言内合法通道——与对 diviner 的治理答复直接矛盾:"effect 签名是检查器推导的,不是手工标注;M3029 结构性推导,**重分类在语言里不可表达**"(docs/moltbook.md:57)。引入 mask = 把当初承诺"不可表达"的事表达出来。
4. **AGENTS §6 硬规则 1("语言语义不可静默改变")的精神**:mask 不改变运行时语义,但改变**声明的含义**——比运行时静默更隐蔽,因为它骗的是审阅者而非机器。

## 3. 与现行机制的逐项冲突(逐个事实来源核实)

### 3.1 M3029 传播推导(v0.46 起):caller 的效果集怎么写?

效果检查是纯推导:被调 `sig.effects` 的缺失项直接成为调用方的 M3029(src/checker.js:1354 `checkEffects`,**源码确认**;缺什么报什么,含结构化 fix 处理)。mask 函数的 `sig.effects` 只有两个选择:

- **写了真实效果**(fs 在签名里):mask 无意义——签名可见,这就是现状。§6.11 当年的核心矛盾("被 mask 的效果在 caller 效果集怎么写?写了 = 可见,不写 = 不可见,但真实效果还在执行")没有第三种答案;
- **不写(签名纯)**:调用 mask 函数的 caller 不被要求 fs——caller 的效果集**缺少一个真实发生的效果**。传播链上每一层的签名都是对事实的系统性低估;调用链越长,审计者看到的"效果真相"偏差越大。

"块级精确"(v0.44 拒绝函数级属性的理由)不解决这个矛盾——粒度再细,mask 存在的意义就是让效果集与事实不一致。

顺带处置变体"**仅入口 mask**"(mask 只允许出现在无调用方的入口函数,如 main/test):机械上确实同时躲开 §3.1 的 caller 两难、§3.2 的契约与 §3.4 的函数值——入口函数没有调用链、不进契约、不作值传递。但它不构成第三种答案:§2 的第一原则冲突原样成立(入口签名恰是审计者读的第一行,`fn main()` 写纯而体里做 IO,仍是签名对事实的系统性隐瞒),且门面用例(库 API 包装内部效果)根本不发生在入口函数上——既不解决冲突也不服务动机,是"少惹麻烦"而不是"成立"。

### 3.2 契约纯性:mask 让契约可以做 IO(健全性破洞)

契约表达式在空效果集下检查(src/checker.js:1259/1267 `contractMode`,`effects: new Set()`,**源码确认**)。**实测**(2026-11-13):`requires` 里调用 `with env` 函数 → `M3029: 此调用需要效果 [env],但函数 "validated" 声明的是 [纯函数]`——契约纯性靠 `sig.effects` 为空这道墙。mask 函数签名纯、体里做 IO:

- **M3029 对它失效**,契约里可以直接调用 → **requires/ensures/invariant 的求值会真实读盘/读网**;
- invariant 在每次 `mut self` 方法退出后重查(GUIDE §6)——**每次方法调用都触发一次 masked IO**。性能与语义双雷;
- M3043 连契约里的 mut 方法都拒绝(实测,tests/run.mjs v51.1)——契约纯性是语言最后的领地,mask 是第一个能在契约里塞副作用的机制。

### 3.3 wasm/C 资格:sig.effects 是单一事实来源,mask 让防线变成巧合

资格分析在 `src/wasm.js` `analyze(opts)`(单一事实来源,wasm 与 C 后端共用,AGENTS §6 硬规则 6):`sig.effects` 非空且不含旗标放行的 ffi/unsafe → 拒绝(src/wasm.js:395-400,**源码确认**)。mask 函数 `sig.effects` 为空:

- 表面通过形状检查;调用图不动点回退会在 `std.fs.*` 调用处拒绝——**但这是因为 std 效果函数本来就不是 Ming 函数(未解析调用 → Unsupported),不是因为设计防了 mask**(**实测**:含 `std.fs.write_file` 的 main 经 `ming cc` → `C1 不支持该程序形态:调用目标 Field`;wasm 同理依赖未解析调用回退)。防线是调用的解析机制给的,不是资格语义给的;
- 一旦未来 std 函数被 wasm import 化(fs bridge 是北星支柱 2 的自然扩张),mask 函数会**静默进入 wasm 沙箱做 IO**——沙箱内没有 fs 实现,运行期炸,且炸点与签名无关;
- C 后端更实质:design §6.8 映射表明确"效果(io/fs)→ C stdio"——masked 函数若进 C 发射,**C 后端成为 IO 的真实执行者而签名无痕**。"不安全代码永不进 AOT 快路径"(design §6.10 安全立场)被 mask 绕过。

要堵上,每个资格路径都要加"mask 感知":要么 mask 函数一律不 eligible(那 mask 函数永远回落 JS——性能税),要么资格分析理解 mask 块(把单一事实来源复杂化)。两个方向都是持续维护负担。

### 3.4 函数值携带效果(v0.51):mask 在值传播下更不可行

v0.51 修复 P0 后,函数类型携带 `effects` 并参与 unify:效果函数值赋给纯函数类型/传纯 HOF 被拒(M3002 显示 `() -> str with env`,**实测** 2026-11-13:纯 `fn apply(f: () -> str)` 收 `read_env` → `M3002: 期望 () -> str,实际 () -> str with env`;tests/run.mjs v51 系列)。mask 函数的 fn 类型携带什么效果集?

- 携带真实效果(fs):"签名看不见"在值传播层又变成可见——与 mask 的定义矛盾,等于 mask 只对直接调用生效,函数值路径退回现状;
- 携带签名效果(空):**撒谎的签名经函数值传遍调用链**——`let g = masked_fn;` 在纯上下文可调用,效果不可见。mask 的不可见性被值传播放大,而函数值正是 v0.51 刚补好的 P0 绕过面。v0.54 闭包洗效果(B4)同一个原理:块内闭包的函数类型携带 unsafe——**携带真实**。mask 与"函数类型 = 效果事实"的既有合同冲突。

### 3.5 v0.54 unsafe 双门禁的对照:先例指向"更显式",不是"更隐身"

unsafe(v0.43 设计 → v0.54 C5 落地)的答案是双门禁:签名 `with unsafe`(M3029 逐层传播)+ 块级 `unsafe { ... }`(M3046)——**危险面在签名与代码两处可见**,审阅者在文件里看到的 `unsafe {` 就是可见面(design §6.10)。unsafe 落地后:

- "安全门面"的真实需求已经有显式形态:`with unsafe` 函数被另一个 `with unsafe` 函数包装,签名逐层传播——门面函数签名诚实带 unsafe/fs,调用方看得到;
- §6.11 曾设想的 `mask [unsafe]` 包装——今天没有动机:ffi 无句柄、std.mem 面极小(alloc/free + 4 方法),没有"必须隐身"的真实 API;
- unsafe 的先例证明:**Ming 处理危险的正交方向是加可见性,不是减**。

### 3.6 治理:diviner 信任边界议题的联动

diviner 的核心质疑(moltbook.md:56-58、:113):"什么能阻止 effect 在评审看到前被重新分类为普通代码?"——答复是"重分类在语言里不可表达;签名差异机械可见;版本提交 = 能力增量 diff"(单维护者模式的审计模型)。mask 的引入:

- 让"效果重分类"成为**语言特性**(块级授权),审计模型从"diff 签名"退化为"diff 全部函数体找 mask 块";
- 多维护者场景若引入 mask,**需要的不是更多信任,而是更多审计工具**(mask 使用清单扫描、块级能力授权记录)——审计人审计审计员的循环,与 Ming"零依赖、机械可见"的治理立场相反;
- 结论:治理场景恰恰更需要签名诚实。diviner 议题是 mask 的**反对**论据,不是保留理由。

## 4. mask 在新模型下更不可行的总结

| 机制 | v0.44 设计时的状态 | 今天(v0.58)的状态 | 对 mask 的影响 |
|------|--------------------|--------------------|----------------|
| M3029 传播 | 已推导(v0.46),mask 依赖逃逸分析评估 | `checkEffects` 结构化推导 + fix 处理,契约/证明/资格全部消费 `sig.effects` | **更不可行**:单一事实来源的消费者从 1 个涨到 4+ 个(checkEffects / 契约 / 资格 / 摘要),每个都要 mask 补丁 |
| 函数值效果 | 不存在(尚有 P0 绕过) | v0.51 闭合:函数类型携带 effects 参与 unify | **更不可行**:值传播让"签名不可见"放大成"全链路不可见" |
| unsafe | 设计稿 | C5 落地,双门禁先例确立 | **更不可行**:先例证明正交方向是加可见性 |
| 资源句柄 | 假设将来有 | ffi 无句柄、fs 无句柄、`lib.fn` API 已删除;唯一句柄 `Join[T]` 已被 M3034 线性纪律 + scoped 块显式解决 | **动机消失**:§6.11 条件 1 要防的东西不存在 |
| 门面用例 | 假设性 | 单维护者 std 无"内部效果外部纯"的真实 API;自举工具显式声明全部效果 | **动机仍是假设** |

v0.44 时 mask 是"待评估的方向";今天它是"被四个既有机制围死、动机又不存在"的负资产。plan §4.2.8 的降级理由("签名不再陈述真实效果;与资格/契约纯性冲突;需独立 ADR/审计")已被本 ADR 逐条证实,且比当时预期的更深。

## 5. 三选一裁决

### 5.1 不做(推荐,**采纳**)

永久删除 Backlog 条目;design §6.11 改写为"已否决"记录(保留历史与理由,指向本 ADR);plan §4.2.9"明确不做"与 §4.3.9 同步。

**理由浓缩**:① 特性定义与第一原则冲突,不可调和(§2);② 与 M3029 推导/契约纯性/资格/函数值四个机制的冲突都是结构性的,每处防线都是补丁(§3);③ 动机(资源句柄包装、安全门面)在 Ming 的 API 设计与单维护者现实中不存在(§1/§3.5);④ 替代方案(显式包装)覆盖全部真实用例,代价是诚实的传播税(§6)。

### 5.2 降级为类型级方案(`Safe<T>` wrapper 语义)(否决)

"用类型把危险消化在内部"的愿望在 Ming 的效果模型下无实现路径:效果是函数级事实,wrapper 类型改变不了被调函数的真实效果,只能让调用方"看不见"——**那就是 mask 换名**,冲突原样继承(契约纯性/资格/函数值/治理四条全部复现)。类型级方案的合法变体是 **sink 参数化**(危险 API 接受策略/凭据类型参数,让"危险点"在类型层显式)——那是 sink API 的设计改进,不是效果屏蔽,与 mask 无关;若未来出现真实需求,应走 adr-002-taint.md 的 sink 面,不走本 ADR。

### 5.3 保留待多维护者治理场景(否决)

见 §3.6:治理场景需要更强的签名诚实,mask 方向相反。**不设"将来若多维护者则重开"的条件承诺**——保留一个自己反对的条目只会制造"它可能还是要做"的持续心智税。真重开需同时满足(写在这里作为门槛,而非承诺):出现真实的"内部效果外部语义纯"API(例如带锁的纯语义数据结构)、独立的 mask 使用审计工具、以及一次推翻 §2/§3 论据的评审——目前看不到任何一条的前景。

## 6. 替代路径:显式包装(覆盖"安全门面"用例)

```ming
use std.fs;

// 门面:签名诚实。内部实现(多次读写、临时文件)对调用方是 fs 效果一行字
fn load_config(path: str) -> Result[str, str] with fs {
    let raw = std.fs.read_file(path)?;
    return Ok(raw.trim());
}

fn main() with io, fs {          // 调用方声明 fs——传播税,design §2.13 明说接受
    match load_config("app.cfg") {
        Ok(cfg) => print(cfg),
        Err(e)  => print("读取失败: \{e}"),
    }
}
```

门面的代价 = 调用链逐层声明效果。这是**被设计接受的税**:效果清单就是审计清单(GUIDE §14),"审计时多看一行 with"远优于"审计时相信一个看不见的 mask 块"。若某 API 的效果真是实现细节(目前没有这样的案例),正确动作是重新设计 API 让它真的纯(如改用不可变结构消除写盘),而不是撒谎。

## 7. 结论与重启条件

**结论:不做。Backlog 条目永久删除;§6.11 存档为已否决设计。**

重启条件(全部满足才重开,当前无一具备):真实用例出现(现有 std/工具链无此类 API)+ 三个 sig.effects 消费方(传播/契约/资格)的 mask 感知方案有独立 ADR + 推翻 §2 原则冲突的评审结论 + mask 使用审计工具先行落地。

**与 ADR-002 的边界**:污点(adr-002-taint.md)是数据级、运行时擦除、签名诚实(污点事实写进类型签名)——与 mask 无共通点;唯一联系是任务书同批交付,且污点方案里"显式声明 Untrusted 形参"与 mask 的"显式消化效果"是相反的哲学示范:前者加可见性,后者减。
